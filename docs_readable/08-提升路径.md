# 08 提升路径：从 IC 0.047 往上走

跑通基线之后，下一个问题必然是「怎么做得更好」。本文按**投入产出比**列出五条路径，每条给出具体改法、预期效果和验证方法。

> 基线：LightGBM + Alpha158 + csi300，IC 0.0468，计成本超额年化 8.07%。
> 全部数字来自本机实测，详见 [指标篇](07-指标篇.md)。

---

## 先纠正一个前提：预测的不是「概率」

Qlib 默认做的是**回归**，不是分类：

[qlib/contrib/model/gbdt.py:19](../qlib/contrib/model/gbdt.py)

```python
def __init__(self, loss="mse", ...):
    self.params = {"objective": loss, ...}     # 默认 mse = 均方误差回归
```

| | 回归（默认） | 分类（可选） |
|---|---|---|
| 输出 | 预测收益率，任意实数（如 `-0.027139`） | 概率，0~1 |
| 配置 | `loss: mse` | `loss: binary` |
| 用法 | 按分数排序，买最高的 N 只 | 概率超阈值就买 |

**两者都能赚钱**，但对标签的要求不同（见路径 ①）。

## 五条路径全景

```
① 标签      ← 要预测什么（决定上限）
② 因子      ← 输入什么信息
③ 模型      ← 怎么学这个映射
④ 组合策略  ← 分数变成持仓
⑤ 交易执行  ← 持仓变成订单
```

| 路径 | 影响 | 难度 | 建议优先级 | 本机验证 |
|---|---|---|---|---|
| ① 标签 | **最大** | 低（改一行） | **1** | ✅ IC +47% |
| ③ 模型 | 中（+10%） | 低（换 2 行） | 2 | ✅ IC +10%，超额 +3.1pp |
| ② 因子 | 大 | 中 | 3 | 未做 |
| ④ 组合策略 | **大** | 中 | 4 | ⚠️ `n_drop` 实测失败 |
| ⑤ 交易执行 | 中 | 高 | 5 | 未做 |

**反直觉但重要**：模型是大家最爱调的，影响反而最小。**标签设计的影响比换模型大得多**（本机实测：改一行标签，IC 提升 47%，超过任何换模型的官方基准提升）。

**同样反直觉**：「成本高」不意味着「降换手就能赚更多」。本机实测硬砍换手导致收益崩掉，原因见下文。

### 成本为什么重要（但不该用 `n_drop` 来省）

看你自己的实测数据：

```
纯选股能力（IC 0.047）    年化 12.60%
扣掉交易成本              年化  8.07%
                          损失 36%
```

成本确实吃掉了三分之一。但**「成本高」不等于「降换手就能赚更多」**——下面的实测证明，用 `n_drop` 硬砍换手会把信号一起砍掉。

> **正确做法：先提升信号质量（改标签周期，已验证 IC +47%），再用平滑的手段控成本。**

## 路径 ④ 组合策略：理解 `n_drop`

### 改法 1：降低换手（最简单，改 1 个数字）

```yaml
strategy:
    class: TopkDropoutStrategy
    kwargs:
        signal: <PRED>
        topk: 50
        n_drop: 2        # ← 从 5 改成 2
```

`TopkDropoutStrategy` 的参数（[qlib/contrib/strategy/signal_strategy.py:74](../qlib/contrib/strategy/signal_strategy.py)）：

| 参数 | 含义 | 默认 |
|---|---|---|
| `topk` | 持有股票数 | 必填 |
| `n_drop` | 每日最多替换几只 | 必填 |
| `hold_thresh` | 最少持有天数 | 1 |
| `only_tradable` | 只交易可交易的 | False |
| `method_sell` / `method_buy` | 卖出/买入选谁 | `bottom` / `top` |

**实测结果（本机验证，不是估算）**：

| n_drop | 日均换手 | 日均成本 | 无成本超额年化（算术） | 计成本超额年化 | 计成本 IR |
|---|---|---|---|---|---|
| 5（基线） | 19.1% | 1.91 bp | 12.60% | **8.07%** | 0.91 |
| 2 | 7.9% | 0.78 bp | 4.46% | **2.60%** | 0.30 |

**结论：仅降 `n_drop` 是失败的。** 换手和成本确实降了一半以上，但收益掉得更狠——计成本超额年化从 8.07% 跌到 2.60%。

**为什么**：`n_drop=2`、`topk=50` 意味着每天最多只换 2 只，不到持仓的 4%。模型每天更新的排序几乎用不上，组合被锁在旧持仓里。看源码 `qlib/contrib/strategy/signal_strategy.py:196-223`，`n_drop` 同时限制每日**买入**和**卖出**只数，是硬上限，不是"降换手"这种软约束。

> **重要**：`n_drop` 正确的用法是「每天需要卖几只」，一般设为 `topk` 的一个合理比例（如 `topk=50`、`n_drop=5`，即每天动 10%）。**不要把它当成成本调节旋钮**。

**真正的降换手手段**（还没验证，按优先级）：

1. **改标签周期**（见路径 ①）——已验证：5 日标签 IC 0.0468 → **0.0690**，计成本超额 8.07% → **10.74%**，且换手基本不变。这是目前唯一验证有效的改进。
2. **`SoftTopkStrategy` 的 `trade_impact_limit`**——按权重渐进调仓，而不是硬限只数。
3. **`hold_thresh`**——限制最短持有天数，比 `n_drop` 更符合直觉。
4. **组合优化器的 `delta` 换手惩罚**——最精细，但需要额外配置成本。

### 改法 2：调持仓集中度

```yaml
topk: 30      # 从 50 降到 30
```

| topk | 特点 |
|---|---|
| 20~30 | 集中，波动大，超额可能更高 |
| 50（当前） | 均衡 |
| 100+ | 分散，接近指数，超额被稀释 |

**IC 不变，但收益曲线形态会明显变化。**

### 改法 3：加持有期约束

```yaml
hold_thresh: 5      # 至少持有 5 天才卖
```

直接压制换手，但也会「锁死」已经变差的持仓，需要权衡。

### 改法 4：换 `SoftTopkStrategy`（带成本约束）

[qlib/contrib/strategy/cost_control.py:8](../qlib/contrib/strategy/cost_control.py)

```yaml
strategy:
    class: SoftTopkStrategy
    module_path: qlib.contrib.strategy.cost_control
    kwargs:
        topk: 50
        risk_degree: 0.95              # 目标仓位比例
        trade_impact_limit: 0.02       # 单只股票单次最大权重变化
        max_sold_weight: 1.0
        buy_method: first_fill
```

**核心优势**：`trade_impact_limit` 给每只股票**单次调仓幅度上限**，天然抑制换手，比 `n_drop` 更平滑（不是一刀切换固定只数，而是按权重渐进调整）。

### 改法 5：用组合优化器分配权重

qlib 内置 [qlib/contrib/strategy/optimizer/optimizer.py:14](../qlib/contrib/strategy/optimizer/optimizer.py)：

| 方法 | 含义 |
|---|---|
| `gmv` | 全局最小方差组合 |
| `mvo` | 均值-方差最优（Markowitz） |
| `rp` | 风险平价 |
| `inv` | 逆波动率加权（默认） |

```python
from qlib.contrib.strategy.optimizer.optimizer import PortfolioOptimizer

optimizer = PortfolioOptimizer(
    method="mvo",
    lamb=1.0,      # 风险厌恶系数，越大越关注收益
    delta=0.02,    # 换手率限制
    alpha=0.001,   # L2 正则
)
```

**`delta` 参数直接控制换手**——这是比 `n_drop` 更精细的手段。

### 改法 6：指数增强（大资金适用）

[qlib/contrib/strategy/signal_strategy.py:374](../qlib/contrib/strategy/signal_strategy.py)

```yaml
strategy:
    class: EnhancedIndexingStrategy
    kwargs:
        model: <MODEL>
        dataset: <DATASET>
        riskmodel_root: ./riskdata      # 需要风险模型数据
        market: csi300
        turn_limit: 0.02                # 换手限制
```

**特点**：在**控制跟踪误差**的前提下追求超额。适合大资金或指数增强产品。

**代价**：需要准备风险模型数据（因子暴露、协方差、特异性风险）。示例见 [examples/portfolio/](../examples/portfolio/)：

```
riskmodel_root/
├── 20210101/
│   ├── factor_exp.pkl      ← 因子暴露
│   ├── factor_cov.pkl      ← 因子协方差
│   ├── specific_risk.pkl   ← 特异性风险
│   └── blacklist.pkl       ← 黑名单（可选）
```

生成脚本：`examples/portfolio/prepare_riskdata.py`。

## 路径 ① 标签：影响最大，改一行

### 当前标签

```
Ref($close, -2) / Ref($close, -1) - 1
```

= **T+1 收盘买入、T+2 收盘卖出**的收益。

### 可改的方向

| 方向 | 表达式 | 预期效果 |
|---|---|---|
| **5 日收益** | `Ref($close,-6)/Ref($close,-1) - 1` | IC 升高，换手大降 |
| **20 日收益** | `Ref($close,-21)/Ref($close,-1) - 1` | IC 更高，容量更大，但回测期变短 |
| **分类标签** | `Greater(Ref($close,-2)/Ref($close,-1)-1, 0.02)` | 输出概率 |
| **行业中性** | 需要额外处理 | IC 降，超额更稳 |
| **周频调仓** | 配合 5 日标签 | 换手降到 1/5 |

### 推荐先试：5 日收益

```yaml
handler:
    kwargs:
        label: ["Ref($close, -6)/Ref($close, -1) - 1"]
```

**为什么**：你现在的瓶颈是成本（19% 日均换手）。5 日标签让交易频率天然降低，是**同时降低换手、提升 IC 信噪比**的手段。

**代价**：标签重叠会导致训练样本自相关，实际有效样本变少。

### 如果想要「概率」

```yaml
model:
    kwargs:
        loss: binary
handler:
    kwargs:
        label: ["Greater(Ref($close,-2)/Ref($close,-1)-1, 0.02)"]
```

输出变成「未来两天涨超 2% 的概率」。

**注意**：`LGBModel` 只支持 `mse` 和 `binary` 两种（[gbdt.py:20](../qlib/contrib/model/gbdt.py)），其他 loss 会抛 `NotImplementedError`。

**分类的额外考虑**：类别不平衡（涨超 2% 的天数可能只占 30%），需要调整 `scale_pos_weight` 或评估时看 AUC/精确率而不是 IC。

## 路径 ② 因子：qlib 最擅长的部分

### 改法 1：换数据集（零代码）

```yaml
handler:
    class: Alpha360      # 从 Alpha158 换过来
```

**实测差异**（CSI300，20 次运行）：

| 模型 | Alpha158 | Alpha360 | 变化 |
|---|---|---|---|
| LightGBM | 0.0448 | 0.0400 | **-11%** |
| ALSTM | 0.0362 | 0.0497 | **+37%** |
| HIST | — | 0.0522 | 最高 |

**关键**：Alpha360 不适合树模型（因子是原始序列，没有工程化），但适合序列模型。详见 [模型篇](05-模型篇.md#第-2-层特征质量也叫因子)。

### 改法 2：换股票池（零代码）

```yaml
market: &market csi500        # 从 csi300
benchmark: &benchmark SH000905
```

**实测**（官方基准）:

| 股票池 | 模型 | IC | 年化收益 |
|---|---|---|---|
| csi300 | LightGBM | 0.0448 | 9.01% |
| csi500 | LightGBM | 0.0399 | **12.84%** |

**IC 降了，但年化升了**——中盘股 alpha 空间更大，但噪声也更多。这是个重要的权衡。

### 改法 3：加自己的因子

```python
from qlib.contrib.data.handler import Alpha158
from qlib.contrib.data.loader import Alpha158DL

class MyAlpha(Alpha158):
    def get_feature_config(self):
        base_f, base_n = Alpha158DL.get_feature_config()

        my_f = [
            "Corr($close, Log($volume+1), 20)",     # 20日价量相关
            "Std($close,10)/Mean($close,10)",        # 10日变异系数
            "Rank($close, 20)",                      # 20日价格分位
            "Corr($close, $vwap, 10)",               # 收盘与均价相关性
            "Slope($volume, 20)/Mean($volume,20)",   # 成交量趋势
        ]
        my_n = ["MY_CORR20", "MY_CV10", "MY_RANK20", "MY_CORRVWAP10", "MY_VOLSLOPE"]

        return base_f + my_f, base_n + my_n
```

YAML：

```yaml
handler:
    class: MyAlpha
    module_path: my_project.handlers
    kwargs: *data_handler_config
```

**加什么因子**（按性价比）：

| 方向 | 例子 | 需要的数据 |
|---|---|---|
| **价量背离** | `Corr($close, $volume, 20)` | OHLCV |
| **波动率结构** | `Std($close,5)/Std($close,20)` | OHLCV |
| **高阶矩** | 偏度、峰度 | OHLCV |
| **基本面** | PE、PB、ROE | 需额外数据 |
| **另类** | 舆情、北向资金 | 需额外数据 |

### 改法 4：因子中性化

把因子对行业、市值做回归，取残差。qlib 没有现成 processor，需要自己写：

```python
class IndustryNeutral(Processor):
    def __init__(self, industry_df):
        self.industry = industry_df

    def __call__(self, df):
        # 按日、按行业做去均值
        return df.groupby([df.index.get_level_values("datetime"),
                           self.industry]).transform(lambda x: x - x.mean())
```

**效果**：IC 会降，但**超额更稳定、更少受行业轮动影响**。

## 路径 ③ 模型：影响中等，但耗时最长

详见 [模型篇](05-模型篇.md)。**本机实测**（同数据、同回测、只换模型）：

| 实验 | IC | ICIR | 计成本超额年化 | 计成本 IR | 耗时 |
|---|---|---|---|---|---|
| LightGBM（基线） | 0.0468 | 0.3816 | 8.07% | 0.91 | ~3 分钟 |
| **DoubleEnsemble** | **0.0515** | 0.4165 | **11.14%** | **1.31** | **~11 分钟** |

**IC +10%，计成本超额年化 +3.1pp，IR 从 0.91 提到 1.31。** 提升真实存在，但代价是训练时间 ×3.7（3 个子模型 + 特征选择）。

**为什么 DoubleEnsemble 更稳**：它不是简单堆模型，而是做了两件事——

1. **样本重加权（SR）**：按样本在损失曲线上的表现分箱，给难学的样本更高权重
2. **特征选择（FS）**：每个子模型前，把 158 个特征按重要性排序，高重要性保留 80%、低重要性只留 40%

所以它比单个 LightGBM 更抗过拟合，IC 和 ICIR 同时提升。代价是每个子模型前要对 158 个特征逐个做置换测试（[double_ensemble.py:192-204](../qlib/contrib/model/double_ensemble.py)），非常耗 CPU。

**换模型只需改 model 段**：

```yaml
model:
    class: DEnsembleModel
    module_path: qlib.contrib.model.double_ensemble
    kwargs:
        base_model: "gbm"
        num_models: 3
        epochs: 28
        # 其余 LightGBM 超参与基线保持一致
```

完整配置见 [examples/exp_doubleensemble.yaml](../examples/exp_doubleensemble.yaml)。

**必须跑多次**（模型有随机性，DoubleEnsemble 的 FS/SR 也有）：

```bash
cd examples && python run_all_model.py run 20 lightgbm Alpha158 csi300
```

**注意看标准差**，不只看均值——TabNet 的 IC 标准差（±0.01）比它有意义的提升还大。

## 路径 ⑤ 交易执行：日频影响小

qlib 提供的执行策略（[qlib/contrib/strategy/rule_strategy.py](../qlib/contrib/strategy/rule_strategy.py)）：

| 策略 | 作用 |
|---|---|
| `TWAPStrategy` | 时间加权平均价拆单 |
| `SBBStrategyEMA` | 基于 EMA 的分批建仓 |
| `ACStrategy` | 算法交易执行 |
| `RandomOrderStrategy` | 随机下单（基准对照） |

**日频回测里基本不起作用**——你就是按收盘价一次性成交，`ffr=1.0` 说明全部成交。

**什么时候需要**：

- 单只股票持仓超过该股日均成交量的 1%
- 需要日内拆单降低冲击成本
- 资金规模大到无法一次性建仓

**判断标准**：看 `ffr`（成交率）。你的 `ffr=1.0`，说明当前规模下不成问题。如果降到 0.8 以下，就该考虑拆单了。

## 推荐实验顺序

按投入产出比，从高到低：

| 步骤 | 改动量 | 预期 | 耗时（本机） |
|---|---|---|---|
| **1. 标签改 5 日收益** | 1 行 | **已验证：IC +47%，超额年化 +2.7pp** | ~4 分钟 |
| **2. 换 DoubleEnsemble** | 换 model 段 | **已验证：IC +10%，超额年化 +3.1pp，IR 0.91→1.31** | ~11 分钟 |
| **3. 1 + 2 组合** | 两处 | 未验证，两个增益可能叠加 | ~12 分钟 |
| **4. `topk: 50 → 30`** | 1 个数字 | 收益曲线形态变化，未验证 | ~4 分钟 |
| **5. `csi300 → csi500`** | 2 处 | IC 降但年化可能升（官方基准） | ~4 分钟 |
| **6. `Alpha158 → Alpha360`** | 1 个词 | 树模型会变差（官方基准） | ~4 分钟 |
| **7. 加 5 个因子** | 写代码 | 不确定，可能 +5% | 1 小时 |
| **8. 加组合优化器** | 配置 | 换手可控 | 半小时 |

**已排除的选项**：`n_drop: 5 → 2` 实测失败（超额年化 8.07% → 2.60%），原因见上文。

**关键原则**：**一次只改一个变量**，否则无法归因。

## 判断改进是否「真的」有效

三件事必须检查，否则容易自欺：

### ① 统计显著性

IC 从 0.0468 提到 0.0500，是真实提升还是随机波动？

```python
from scipy import stats
ic = pd.read_pickle(base + "sig_analysis/ic.pkl").dropna()
t, p = stats.ttest_1samp(ic, 0)
```

你的基线 `t = 11.24`，非常显著。**新实验的 t 值必须同样显著，且 IC 提升幅度要超过标准差才可信。**

### ② 分年稳定性

```python
print(ic.groupby(ic.index.year).mean())
```

如果新方案只是某一年变好，其他年份变差，那不可信。

### ③ 换手与成本的实际变化

```python
report = pd.read_pickle(base + "portfolio_analysis/report_normal_1day.pkl")
print(report[["turnover", "cost"]].mean())
```

**如果 IC 提升了但年化没提升，多半是成本吃掉了。**

## 最重要的结论

本机做了三个对照实验，结果推翻了两个常见直觉：

| 做法 | IC | 计成本超额年化 | 结论 |
|---|---|---|---|
| 降换手（`n_drop: 5 → 2`） | 0.0468（不变） | 8.07% → **2.60%** | ❌ 失败 |
| 改标签（2 日 → 5 日收益） | 0.0468 → **0.0690** | 8.07% → **10.74%** | ✅ 有效 |
| 换模型（LightGBM → DoubleEnsemble） | 0.0468 → **0.0515** | 8.07% → **11.14%** | ✅ 有效 |

**两个反直觉的发现**：

1. **降换手不等于赚更多**——硬压换手会把信号一起吃掉了
2. **换模型的收益比预期大**——官方基准说 +16% IC，本机实测 +10% IC 但计成本超额年化 +38%（8.07% → 11.14%），因为 DoubleEnsemble 更好的信号质量在扣成本后仍然保留

**下一步建议**：把「5 日标签」和「DoubleEnsemble」组合起来——两者的增益来源不同（一个是标签周期，一个是抗过拟合），可能叠加。
