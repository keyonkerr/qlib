# 01 入门介绍：Qlib 是什么

## Qlib 是什么

`Qlib` 是一个**面向 AI 的量化投资平台**，目标是让研究者能快速试验自己的投资想法。

它不是策略库，也不是交易系统，而是**一条完整的量化研究流水线**：从原始行情数据 → 因子计算 → 模型训练 → 预测信号 → 组合回测 → 绩效分析。

**核心抽象**：把「预测股票未来收益」当成一个**监督学习问题**。

```
输入：每只股票每天的 158 个因子
输出：一个分数（预测未来收益）
训练：用历史数据学「因子 → 收益」的映射
使用：每天给所有股票打分，买分数最高的
```

---

## 四层架构

```
┌─────────────────────────────────────────────────────────┐
│  Interface 层（接口层）                                   │
│  Analyser：预测信号、组合、执行结果的分析报告               │
├─────────────────────────────────────────────────────────┤
│  Workflow 层（工作流层）                                  │
│  Information Extractor ← 提取数据给模型                   │
│  Forecast Model        ← 产生预测信号（alpha、风险）        │
│  Decision Generator    ← 生成交易决策（组合、订单）         │
│  Execution Env         ← 执行决策（模拟或实盘市场）         │
├─────────────────────────────────────────────────────────┤
│  Learning Framework 层（学习框架层）                       │
│  Forecast Model 和 Trading Agent 在这里被训练              │
│  支持监督学习和强化学习两种范式                             │
├─────────────────────────────────────────────────────────┤
│  Infrastructure 层（基础设施层）                           │
│  DataServer：高性能数据存取                                │
│  Trainer：可控的训练过程                                   │
└─────────────────────────────────────────────────────────┘
```

**设计原则**：各模块**松耦合**，每个组件都可以单独使用。你可以只用一个 `DataHandler` 取数据，也可以只用一个 `Model` 做训练，不必走完整条流水线。

**Strategy 和 Executor 可以嵌套**：例如日频组合管理（外层策略）→ 日内订单执行（内层策略），这是高频交易的基础。

## 本仓库的实际跑法

核心入口是 **`qrun`**：用一个 YAML 描述整条流水线，一条命令跑完。

```yaml
qlib_init:              # ① 初始化：数据在哪
    provider_uri: "~/.qlib/qlib_data/cn_data"
    region: cn

task:
    model:              # ② 模型：用什么学
        class: LGBModel
    dataset:            # ③ 数据：特征、标签、训练/验证/测试切分
        class: DatasetH
    record:             # ④ 记录：存预测、算 IC、做回测
        - class: SignalRecord
        - class: SigAnaRecord
        - class: PortAnaRecord
```

运行：

```bash
qrun my_config.yaml
```

它内部执行的是 [qlib/model/trainer.py](../qlib/model/trainer.py) 的 `_exe_task`，按顺序做：

```
① qlib.init()          → 加载配置、校验数据
② 构造 Dataset         → 算因子、加工、切片
③ 训练模型             → model.fit(dataset)
④ 执行 Record 链       → 存预测 → 算 IC → 回测
```

每一步的细节见 [快速开始](02-快速开始.md)。

## 「训练模型」到底在做什么

**先破除一个误解**：Qlib 里的「训练」和 ChatGPT 那类大语言模型**完全无关**。

| | LLM（ChatGPT 这类） | Qlib 里的模型（LightGBM） |
|---|---|---|
| 模型类型 | 神经网络（Transformer） | **决策树集成** |
| 参数量 | 几千亿 | 几万到几十万 |
| 训练数据 | 几万亿 token 文本 | **170 万行数字表格** |
| 输入 | 文字序列 | **158 个数字** |
| 输出 | 下一个 token 的概率 | **1 个数字（收益率预测）** |
| 训练时间 | 几个月 + 上千张 GPU | **1 分钟 + 一个 CPU 核** |
| 训练目标 | 预测下一个词 | 预测股票涨跌 |

**LightGBM 不懂语言、不懂语义、没有任何「理解」能力。它就是一个函数拟合器。**

### 梯度提升决策树的实际过程

```
第 1 步：用训练数据建第一棵树
    规则是从数据里自动「切」出来的，例如：
    「如果 MA5 > 1.02 且 STD20 < 0.03，则预测收益 = +0.8%」

第 2 步：算每行数据的残差
    真实收益 1.2%，第一棵树预测 0.8%，残差 = +0.4%

第 3 步：再建一棵树，专门拟合这个残差
    「如果 RSV5 > 0.8 且 VOLUME 上升，则修正 +0.3%」

第 4 步：重复，直到验证集不再改善

最终预测 = 第 1 棵树 + 第 2 棵树 + ... + 第 N 棵树
```

**关键**：这些「如果…则…」规则**不是人写的**，是算法从 170 万行数据里自动搜出来的。

### 训练代码只有几行

[qlib/contrib/model/gbdt.py:77](../qlib/contrib/model/gbdt.py)：

```python
self.model = lgb.train(
    self.params,        # 超参：树多深、学多快、正则多强
    ds[0],              # 训练数据（170 万行 × 158 列 + 1 列标签）
    num_boost_round=1000,
    valid_sets=ds,      # 验证集，用于早停
)
```

**整个「训练」就是调用 `lgb.train()` 这一个函数。** 没有神经网络、没有反向传播、没有 GPU、没有 token。

### 一句话理解

**把 Qlib 的「训练」理解成 Excel「回归分析」的放大版**：输入一堆列，输出一个预测值，算法自动找公式。

它唯一的「智能」在于：**能从 170 万行里发现人眼看不到的 158 维交互模式**。但它不理解股票、不理解公司、不理解经济——它只是在拟合数字。

---

## Qlib 不提供什么

理解边界同样重要：

| 不是 | 说明 |
|---|---|
| **不是策略库** | 只提供 `TopkDropoutStrategy` 等示例策略，不是拿来就能赚钱的成品 |
| **不是交易系统** | 回测是模拟，不对接券商接口（有 `online` 模块但需要自行接入） |
| **不是数据源** | 提供的是 Yahoo Finance 抓的示例数据，质量有限，生产环境要自己接 |
| **不是「AI 预测股价」** | 模型只拟合数字，不「理解」市场；IC 0.05 意味着 65% 的日子方向对，不是稳赚 |
