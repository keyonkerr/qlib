## 1. 认识官方示例

官方示例全在 `examples/benchmarks/` 下，**26 个模型，每个一个文件夹**：

```
examples/benchmarks/
├── LightGBM/
│   └── workflow_config_lightgbm_Alpha158.yaml   ← 我们跑这个
├── XGBoost/
├── CatBoost/
├── LSTM/
├── Transformer/
└── ... 共 26 个
```

**每个文件夹的用法完全相同：一条 `qrun` 命令。**

### 官方配置长什么样

打开 `examples/benchmarks/LightGBM/workflow_config_lightgbm_Alpha158.yaml`，只有 70 行，分 5 块：

```yaml
# ① 数据在哪
qlib_init:
    provider_uri: "~/.qlib/qlib_data/cn_data"
    region: cn

# ② 股票池和基准
market: &market csi300          # 沪深300
benchmark: &benchmark SH000300

# ③ 因子配置
data_handler_config: &data_handler_config
    start_time: 2008-01-01     # 数据范围
    end_time: 2020-08-01
    fit_start_time: 2008-01-01 # 标准化参数的拟合区间
    fit_end_time: 2014-12-31
    instruments: *market

# ④ 策略 + 回测
port_analysis_config: &port_analysis_config
    strategy:
        class: TopkDropoutStrategy
        module_path: qlib.contrib.strategy
        kwargs: {signal: <PRED>, topk: 50, n_drop: 5}
    backtest:
        start_time: 2017-01-01
        end_time: 2020-08-01
        account: 100000000
        benchmark: *benchmark
        exchange_kwargs: {limit_threshold: 0.095, open_cost: 0.0005, close_cost: 0.0015, min_cost: 5}

# ⑤ 模型 + 数据集切分 + 要记录什么
task:
    model:
        class: LGBModel
        module_path: qlib.contrib.model.gbdt
        kwargs: {loss: mse, learning_rate: 0.2, max_depth: 8, num_leaves: 210, ...}
    dataset:
        class: DatasetH
        module_path: qlib.data.dataset
        kwargs:
            handler: {class: Alpha158, module_path: qlib.contrib.data.handler, kwargs: *data_handler_config}
            segments:
                train: [2008-01-01, 2014-12-31]
                valid: [2015-01-01, 2016-12-31]
                test:  [2017-01-01, 2020-08-01]
    record:
        - {class: SignalRecord, ...}
        - {class: SigAnaRecord, ...}
        - {class: PortAnaRecord, ...}
```

**`&market` / `*market` 是 YAML 锚点**：定义一次，多处引用。改 `market: csi500` 就全局生效。

## 2. 直接跑官方原版会遇到的问题

官方配置在 Linux 上开箱即用，但在你这台 Windows 机器上有两个坑：

| 坑 | 原因 | 后果 |
|---|---|---|
| `kernels` 默认 = CPU核数-2 = **22** | `qlib/config.py:182` | 开 22 个 worker 进程，吃内存 |
| 新版 MLflow 拒绝文件后端 | qlib 不锁 mlflow 版本 | 报 `MlflowException: filesystem tracking backend...` |

**所以直接跑官方 yaml 不安全。** 正确做法是复制一份，改两个值。

---

## 3. 正确做法：复制 + 微调

### 3.1 复制官方配置

```bash
cd examples
cp benchmarks/LightGBM/workflow_config_lightgbm_Alpha158.yaml my_lightgbm.yaml
```

### 3.2 改两个值

打开 `examples/my_lightgbm.yaml`，只改这两处：

**改动 1 —— 加 `kernels: 1`**

```yaml
qlib_init:
    provider_uri: "~/.qlib/qlib_data/cn_data"
    region: cn
    kernels: 1                  # ← 新增这行
```

**改动 2 —— 降低 LightGBM 线程数**

```yaml
    model:
        kwargs:
            ...
            num_threads: 2      # ← 官方是 20，改成 2
```

**其他一个字都不要改。** 这样跑出来的结果才是"官方结果"。

### 3.3 运行

```bash
cd examples
```

```bash
MLFLOW_ALLOW_FILE_STORE=true OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 python -m qlib.cli.run my_lightgbm.yaml
```

**为什么用 `python -m qlib.cli.run` 而不是 `qrun`**：`qrun` 是 pyenv 的 shim，在 Git Bash 下容易被搞坏。`python -m` 等价且更可靠。

**为什么加 `MLFLOW_ALLOW_FILE_STORE=true`**：让新版 MLflow 允许写 `./mlruns/` 目录。

## 5. 四个数字怎么读

### 5.1 信号质量（IC 那一组）

```
IC        = 0.0484
ICIR      = 0.3966
Rank IC   = 0.0503
Rank ICIR = 0.4224
```

**IC 的定义**：每天，把模型给 300 只股票的预测分数，和它们实际涨跌算一个相关系数。一年 252 天，算 252 个相关系数，IC 就是这些数的**平均值**。

| IC 值 | 评价 |
|---|---|
| < 0.02 | 没用 |
| 0.02 ~ 0.03 | 勉强 |
| **0.03 ~ 0.05** | **可用** ← 我们在这 |
| > 0.05 | 好 |
| > 0.10 | 可疑（大概率有前视偏差） |

**ICIR = IC均值 / IC标准差**，衡量稳定性。0.40 表示"这个信号大部分时间都有效"。

**Rank IC 用排名算相关性**（Spearman），比 IC 更贴近选股（你只关心排序）。

### 5.2 回测三组（这是重点）

| 组 | 年化收益 | IR | 最大回撤 | 含义 |
|---|---|---|---|---|
| 基准（沪深300） | 11.36% | 0.60 | -37.05% | 什么都不做，直接买指数 |
| 超额（不计成本） | **17.29%** | 1.92 | -9.81% | 模型的纯选股能力 |
| 超额（计成本） | **12.63%** | 1.40 | -10.82% | 实盘能拿到的 |

**关键在第二行到第三行的落差**：

```
17.29%  →  12.63%      损失 4.66 个百分点
```

这 4.66 个点就是**交易成本**（手续费 + 买卖价差）。

**这个落差告诉你**：`topk=50, n_drop=5` 的换手率下，成本吃掉约 27% 的毛收益。想提高实盘收益，**降低换手比提高模型精度更有效**。

### 5.3 三个指标的定义

| 指标 | 公式 | 意义 |
|---|---|---|
| `annualized_return` | 日均收益 × 252 | 年化收益 |
| `information_ratio` | 日均/日标准差 × √252 | 每单位风险的超额收益，**>1 算优秀** |
| `max_drawdown` | 净值从峰值的最大跌幅 | 最坏情况下亏多少 |

## 6. 产物在哪

跑完后：

```bash
ls examples/mlruns/*/*/artifacts/
```

```
config                       ← 这次实验的完整配置（可复现）
params.pkl                   ← 训练好的 LightGBM 模型
pred.pkl                     ← 预测分数（26万个值）
label.pkl                    ← 真实标签
sig_analysis/ic.pkl          ← 880 个日度 IC
sig_analysis/ric.pkl         ← 880 个日度 Rank IC
portfolio_analysis/report_normal_1day.pkl    ← 每日收益明细
portfolio_analysis/positions_normal_1day.pkl ← 每日持仓
metrics/                     ← 标量指标
```

### 自己读这些产物

```python
import pandas as pd, glob

base = glob.glob("examples/mlruns/*/*/artifacts")[0]

# 预测值
pred = pd.read_pickle(f"{base}/pred.pkl")
print(pred.head())

# 每日 IC，看分布
ic = pd.read_pickle(f"{base}/sig_analysis/ic.pkl")
print(ic.describe())
print("IC 为正的天数占比:", (ic > 0).mean())

# 回测明细
report = pd.read_pickle(f"{base}/portfolio_analysis/report_normal_1day.pkl")
print(report[["return", "cost", "turnover"]].tail())
```

## 7. 跑第二个模型（理解"只换模型"）

官方示例的核心用法就是：**同一套流程，只换模型**。

### 7.1 复制配置，换模型段落

```bash
cd examples
cp my_lightgbm.yaml my_xgboost.yaml
```

先装 xgboost：

```bash
python -m pip install xgboost
```

然后把 `task.model` 整段换成：

```yaml
    model:
        class: XGBModel
        module_path: qlib.contrib.model.xgboost
        kwargs:
            eta: 0.0421
            max_depth: 8
            subsample: 0.8789
            colsample_bytree: 0.8879
            lambda: 205.6999
            alpha: 580.9768
            n_estimators: 1000
            nthread: 2
```

（完整参数见 `examples/benchmarks/XGBoost/workflow_config_xgboost_Alpha158.yaml`）

### 7.2 跑

```bash
MLFLOW_ALLOW_FILE_STORE=true OMP_NUM_THREADS=2 python -m qlib.cli.run my_xgboost.yaml
```

### 7.3 对比

官方 benchmark 表里两者的成绩：

| 模型 | IC | Rank IC | 年化收益 | IR |
|---|---|---|---|---|
| LightGBM | 0.0448 | 0.0469 | 9.01% | 1.02 |
| XGBoost | 0.0498 | 0.0505 | 7.80% | 0.91 |

**注意一个有意思的现象**：XGBoost 的 IC 更高（信号更准），但年化收益更低。这说明选股准不等于赚钱多——收益还取决于持仓集中度、换手、风险暴露。

## 8. 常见错误对照表

| 报错 | 原因 | 解决 |
|---|---|---|
| `ValueError: n_jobs == 0` | `kernels: 0` | 改 `kernels: 1` |
| `MlflowException: filesystem tracking backend ... maintenance mode` | 新版 MLflow | 加 `MLFLOW_ALLOW_FILE_STORE=true` |
| `ModuleNotFoundError: qlib.data._libs.rolling` | Cython 扩展丢失 | 重新编译（见 0.1） |
| 进程爆满 / 内存耗尽 | `kernels` 太大 | `kernels: 1` |
| `FileNotFoundError: ... cn_data` | 数据未下载 | 见 0.2 |
| `ModuleNotFoundError: xgboost` | 未装该模型依赖 | `pip install xgboost` |

## 9. 一句话总结

**官方示例的用法：**

```bash
cd examples
cp benchmarks/<模型>/workflow_config_<模型>_<数据集>.yaml my_exp.yaml
# 改 kernels: 1 和 num_threads: 2
MLFLOW_ALLOW_FILE_STORE=true python -m qlib.cli.run my_exp.yaml
```

**每次跑完看三个东西：**
1. 控制台打印的 IC / Rank IC（信号质量）
2. 三组回测的额外收益（赚钱能力）
3. `mlruns/` 里的产物（可复查）

**换模型 = 只改 yaml 的 `task.model` 那一段。**
