# 11 可视化篇：把训练结果画出来

前面几篇讲的都是**数字**（IC、超额年化、IR）。数字适合判断好坏，图形适合看**结构**——分组收益是不是单调、IC 是稳定还是靠少数好日子、回撤发生在哪一段、预测分数换手有多快。本文把 qlib 自带的全部可视化方式整理成一份可执行手册，全部在本机实测跑通。

> 本文所有图都由本机实验 `173385501991978669 / a2c2a0928cda4dcbb7a8623548aa90ce` 生成，产物可直接复现。
> 指标本身的含义见 [指标篇](07-指标篇.md)，本文只讲怎么画、图怎么看。

---

## 一分钟上手

```bash
cd examples
../.venv/bin/python report_graphs.py --out renders
```

`report_graphs.py` 是配套的批处理脚本（见本文最后一节）。它会自动找到最新一次完成且带 `pred.pkl` 的训练，一次生成 14 张图到 `examples/renders/`。用浏览器打开任意 `.html` 即可，图是交互式的（可缩放、可悬停看数值、可框选区间）。

第一次跑之前确认依赖：

```bash
.venv/bin/pip install "plotly<7" statsmodels
```

这是官方 `pip install .[analysis]` 的内容（[pyproject.toml:108](../pyproject.toml)）。

## 全景：四类可视化，各管一件事

| 类别 | 看什么 | 工具 | 需要的数据 |
|---|---|---|---|
| **模型质量图** | 预测分数本身好不好 | `qlib.contrib.report` | `pred.pkl` + `label.pkl` |
| **回测结果图** | 策略赚不赚钱、怎么赚的 | `qlib.contrib.report` | `report_normal.pkl`（+ position） |
| **实验对比** | 多次实验横向比较 | MLflow UI | `mlruns/` 目录 |
| **训练过程** | 模型训练时内部发生了什么 | TensorBoard | 仅 TRA / RL 模型有 |

**分工原则**：单次训练质量看报告图；多次实验比谁强用 MLflow；调模型结构才需要 TensorBoard。

## 一、`qlib.contrib.report`：官方 Graphical Reports

官方文档页是 [docs/component/report.rst](../docs/component/report.rst)，快速入门 [docs/introduction/quick.rst:84](../docs/introduction/quick.rst) 直接把「跑 `workflow_by_code.ipynb` 看图」写成标准流程。

### 数据准备（所有函数的前提）

六个报告函数都吃同一个约定：

- 索引是 **MultiIndex**，名字为 `[instrument, datetime]`
- 列名必须是 **`label`** 和 **`score`**（不是 `LABEL0`）

从 recorder 取出来的原始列名不符合要求，必须改名：

```python
import pandas as pd
import qlib
from qlib.workflow import R

qlib.init(provider_uri="~/.qlib/qlib_data/cn_data", region="cn")

rec = R.get_recorder(recorder_id="a2c2a0928cda4dcbb7a8623548aa90ce",
                     experiment_id="173385501991978669")

pred  = rec.load_object("pred.pkl")    # 列名 'score'
label = rec.load_object("label.pkl")   # 列名 'LABEL0'

pred_label = pd.concat([label, pred], axis=1, sort=True).reindex(label.index)
pred_label.columns = ["label", "score"]     # ← 这一行不能省

report_normal = rec.load_object("portfolio_analysis/report_normal_1day.pkl")
```

**三个必须注意的点**：

1. **必须在 `examples/` 目录下运行**。qlib 从当前工作目录找 `mlruns`，在仓库根目录会报 `No valid experiment found`。
2. **列名不改会报 `KeyError: 'label'`**。这是第一次用最容易踩的坑，因为 `pred.pkl` 里叫 `score` 是对的，但 `label.pkl` 里叫 `LABEL0`。
3. **`positions_normal_1day.pkl` 需要 `trusted=True`**。新版 qlib 用受限 unpickler 加载 artifact；`pred.pkl` / `label.pkl` / `report_normal.pkl` 是纯数据可以直接读，含 `Position` 对象的 position 文件必须显式声明信任：

```python
positions = rec.load_object("portfolio_analysis/positions_normal_1day.pkl", trusted=True)
```

### 六个函数总览

| 函数 | 输入 | 出几张图 | 回答什么问题 |
|---|---|---|---|
| `analysis_model.model_performance_graph` | `pred_label` | 7 | 分数分层能力、IC 质量、预测稳定性 |
| `analysis_position.score_ic_graph` | `pred_label` | 1 | 逐日 IC 长什么样 |
| `analysis_position.report_graph` | `report_normal` | 1 | 赚了多少、回撤多大、换手多高 |
| `analysis_position.risk_analysis_graph` | `report_normal` + 月度分析表 | 5 | 风险指标水平、月度表现分布 |
| `analysis_position.cumulative_return_graph` | `positions` + report + label | 多 | 买入/卖出/持有分别贡献了什么 |
| `analysis_position.rank_label_graph` | `positions` + label | 3 | 买卖的股票在当日收益排名里处于什么位置 |

下面逐个说清楚**图里每一根线是什么**、**该怎么判断**。

## 二、模型质量图：`model_performance_graph`

这是信息量最大的一张组合图，一次给 7 张（默认只画前 3 组中的 `group_return` + `pred_ic` + `pred_autocorr`）。

```python
from qlib.contrib.report import analysis_model, analysis_position

figs = analysis_model.model_performance_graph(
    pred_label,
    graph_names=["group_return", "pred_ic", "pred_autocorr", "pred_turnover"],
    show_notebook=False,      # 返回 Figure 列表；True 则直接在 notebook 里渲染
)
```

### 参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `graph_names` | `["group_return", "pred_ic", "pred_autocorr"]` | 选哪几组图 |
| `N` | 5 | 分几组 |
| `rank` | `False` | `True` 时改用 Rank IC 口径 |
| `reverse` | `False` | `True` 时分数取反（做空信号） |
| `lag` | 1 | 自相关的滞后天数 |
| `show_notebook` | `True` | `True` 内嵌显示；`False` 返回 `Figure` 列表 |
| `show_nature_day` | `False` | 横轴是否显示非交易日（周末） |

⚠️ **`graph_names` 有限制**：只能取注册表里的四个名字 `group_return` / `pred_ic` / `pred_autocorr` / `pred_turnover`。这是近期为安全加的约束，传其他名字会直接抛 `ValueError`。想加自定义图必须往 `GRAPH_FUNCTIONS` 里注册（[analysis_model_performance.py:272](../qlib/contrib/report/analysis_model/analysis_model_performance.py)），扩展示例见 [docs/start/config_migration.rst:258](../docs/start/config_migration.rst)。

### 七张图分别是什么

| # | 图的标题 | 内容 | 怎么看 |
|---|---|---|---|
| 1 | **Cumulative Return** | Group1~5 分组累计收益 + `long-short` + `long-average` | Group1 线要在 Group5 上方，且五组**单调**排列；long-short 单调向上说明分层能力稳定 |
| 2 | （无标题） | long-short / long-average 的日收益分布 | 分布中心应明显偏右；如果有很长的左尾，说明少数日子亏得很惨 |
| 3 | **Information Coefficient (IC)** | 逐日 IC 柱状时序 | 应在 0 上下小幅波动。**连续多个月为负**是危险信号 |
| 4 | **Monthly IC** | 月度平均 IC 热力图（行=年，列=月） | 颜色整体偏正、没有成片负值。本机 2020 年多数月份为正 |
| 5 | （无标题） | IC 分布直方图 + **IC 正态 QQ 图** | 分布应大致对称居中于正数；QQ 点贴近直线说明 IC 接近正态，均值 IC 的 t 检验才有效 |
| 6 | **Auto Correlation** | 今日分数与 N 日前分数的排名相关 | **越高说明信号越"粘"，换手越低**。0.5 以上意味着分数隔一天还基本不变 |
| 7 | **Top-Bottom Turnover** | 多头组与空头组的换手率 | 越高说明持仓变动越快，交易成本越高 |

**第 1 张图最重要**。它是「分层能力」的直接证据：如果 Group1（最高分）和 Group2 的线缠在一起，说明模型区分不出最顶端的股票，而实盘只会买最顶端那一批——这种情况即使 IC 还不错，实际收益也会打折。

**第 6、7 张图联起来看成本**。自相关高 → 换手低 → 成本低。本机基线（2 日标签）的换手明显高于 5 日标签，这是 5 日标签计成本超额更高的原因之一（见 [08 提升路径](08-提升路径.md)）。

## 三、`score_ic_graph`：逐日 IC 曲线

只依赖分数，不需要回测，训练完立刻能看：

```python
figs = analysis_position.score_ic_graph(pred_label, show_notebook=False)
```

一张图，两条线：

- **ic** —— 逐日 Pearson 相关
- **rank_ic** —— 逐日 Spearman 秩相关

**怎么看**：关注三件事——均值是否为正（方向对不对）、波动幅度（稳定性）、以及**有没有明显的时段性崩坏**。如果某几个月的 IC 连续为负，说明模型在那段行情里失效了，这是单看月度平均数字发现不了的。

与 `model_performance_graph` 里的第 3 张图内容重叠，但这里同时给了 Rank IC，且不依赖 `statsmodels`。

## 四、回测结果图：`report_graph`

```python
figs = analysis_position.report_graph(report_normal, show_notebook=False)
```

需要 `report_normal` 含 `return` / `cost` / `bench` / `turnover` 四列——就是 `PortAnaRecord` 的产物，**跑过回测才有**。

一张大图，10 条曲线（本机实测的 trace 名）：

| 曲线 | 含义 |
|---|---|
| `cum bench` | 基准累计收益（如 csi300） |
| `cum return wo cost` | 组合累计收益，**不含**成本 |
| `cum return w cost` | 组合累计收益，含成本 |
| `return wo mdd` / `return w cost mdd` | 对应的最大回撤序列 |
| `cum ex return wo cost` / `w cost` | 相对基准的**超额**累计收益 |
| `cum ex return wo cost mdd` / `w cost mdd` | 超额收益的回撤序列 |
| `turnover` | 换手率 |

图上有两块阴影区：上方阴影是「不含成本组合」的最大回撤区间，下方阴影是「不含成本超额」的最大回撤区间。

**怎么看**：

1. 先看 `cum return w cost` 有没有持续跑在 `cum bench` 上方——这是**最基本的判断**。
2. 再看 `cum return wo cost` 和 `w cost` 之间的缺口——**这就是成本吃掉的部分**。本机基线这条缺口约 36%。
3. 最后看超额曲线（`cum ex return`）的斜率是否**平稳向上**。如果斜率只在某几段陡增，收益集中在少数时段，实盘可靠性要打折扣。

> qlib 的所有累计收益都用**求和**而不是连乘（[docs/component/report.rst](../docs/component/report.rst) 明确说明），目的是避免长期图被指数放大的视觉误导。所以曲线数值与「真实复利」略有差异，看形状比看绝对值更重要。

## 五、`risk_analysis_graph`：风险指标 + 月度分布

```python
port_analysis = rec.load_object("portfolio_analysis/port_analysis_1day.pkl")
```

**注意参数**：`report_normal_df` 只给月度图；要加上第一张风险指标柱状图，必须同时传 `analysis_df`（recorder 里的 `port_analysis_1day.pkl`）。

实测输出 5 张：

| # | 图 | 内容 |
|---|---|---|
| 1 | （无标题） | 四个风险指标柱状图并排：`annualized_return` / `max_drawdown` / `information_ratio` / `std`，分「含成本」和「不含成本」两组 |
| 2 | `annualized_return` | 月度年化收益折线 |

| 4 | `information_ratio` | 月度 IR 折线 |

**怎么看**：第 1 张是**和 [指标篇](07-指标篇.md) 里那张表对应的图形版**，数字熟悉后一眼就能定位。第 2~5 张是**稳定性检查**——如果月度年化收益忽高忽低、某几个月深度为负，说明策略对行情依赖大。

## 六、持仓类图：`cumulative_return_graph` 与 `rank_label_graph`

这两个需要 position 数据（`trusted=True`）。

### `cumulative_return_graph`：钱是怎么赚来的

```python
positions = rec.load_object("portfolio_analysis/positions_normal_1day.pkl", trusted=True)
label_data = label.rename(columns={"LABEL0": "label"})

figs = analysis_position.cumulative_return_graph(
    position=positions,
    report_normal=report_normal,
    label_data=label_data,
    show_notebook=False,
)
```

分成买入、卖出、持有三组图。每组上方是**持仓加权收益的累计**，下方是**权重总和**。

**关键读法（官方文档特别说明）**：

- **卖出图里 `y < 0` 表示盈利**（因为你卖掉了赚钱的股票）
- 其他图里 `y > 0` 表示盈利
- 右侧直方图的红线是均值

**这组图回答**：收益主要来自「买对了」还是「卖对了」？如果买入组贡献很大而卖出组贡献很小，说明策略靠选股；反之说明靠择时退出。

### `rank_label_graph`：选股精度

```python
figs = analysis_position.rank_label_graph(
    position=positions,
    label_data=label_data,
    show_notebook=False,
)
```

三张图：**hold / buy / sell**。纵轴是该组股票在当日**收益排名分位**（label-rank-ratio，%）。

**怎么看**：

- **buy 组的分位应显著低于 50%**（买的股票当天涨得好，排名靠前）
- **sell 组的分位应显著高于 50%**（卖的股票确实弱）
- **hold 组应在中间**

如果 buy 组和 hold 组的分位几乎一样，说明「买入决策」没有带来额外信息，模型只是在维持一个还不错的组合。

## 七、MLflow UI：横向对比多次实验

```bash
cd examples
MLFLOW_ALLOW_FILE_STORE=true ../.venv/bin/mlflow ui --backend-store-uri mlruns
```

浏览器打开 <http://127.0.0.1:5000>。

⚠️ **`mlflow` 命令不在系统 PATH 上**，必须用 `.venv/bin/mlflow`。直接敲 `mlflow` 会 `command not found`。

`MLFLOW_ALLOW_FILE_STORE=true` 是给 mlflow 3.x 用的：文件后端从 2026 年 2 月起标记为 deprecated，不设这个变量会出现 FutureWarning（不设也能跑，只是有警告）。

### 能看到什么

- **左栏 Experiments**：本机有 3 个（`0` 是空壳，另外两个才有数据）
- **每个 run 的 metrics**：IC / ICIR / Rank IC / 超额年化 / IR / 回撤，都是标量曲线
- **Artifacts 页**：能直接下载 `pred.pkl`、`label.pkl`、`report_normal.pkl`、`portfolio_analysis/` 下的全部文件
- **选中多个 run → Compare**：同一张图上叠加对比

### 什么时候用 MLflow、什么时候用报告图

| 需求 | 用哪个 |
|---|---|
| 这次训练比上次好吗 | MLflow Compare |
| 10 组参数哪组最优 | MLflow，按指标排序 |
| 这次训练的模型分层能力怎么样 | `model_performance_graph` |
| 回撤发生在哪一段 | `report_graph` |
| 收益是靠买还是靠卖 | `cumulative_return_graph` |

**一句话**：MLflow 管「哪个好」，报告图管「为什么好」。

## 八、训练过程可视化（仅特定模型）

绝大多数 qlib 模型**没有**训练过程图，只有两类例外：

## 十、导出与保存

三个报告函数在 `show_notebook=False` 时都返回 `plotly.graph_objs.Figure` 列表（`report_graph` 和 `score_ic_graph` 返回只含一个元素的 tuple）。保存方式：

```python
# 存成 html（交互式，推荐）
fig.write_html("report.html", include_plotlyjs="cdn")

# 存成静态图片（需要 kaleido 包）
fig.write_image("report.png", width=1600, height=900)

# 浏览器里直接打开
import plotly.io as pio
pio.show(fig)
```

`include_plotlyjs="cdn"` 让 html 只有几十 KB 而不是 3 MB（从 CDN 加载 plotly.js），适合提交到仓库或发给人看。

## 十一、配套脚本 `report_graphs.py`

完整脚本在 [examples/report_graphs.py](../examples/report_graphs.py)，本文所有结论都用它验证过。

### 用法

```bash
cd examples

# 自动挑所有实验中最新一次完整运行，图存到 renders/
../.venv/bin/python report_graphs.py --out renders

# 指定实验（会挑该实验里最新的一次）
../.venv/bin/python report_graphs.py --experiment 740576277429403079 --out renders

# 指定某一次 run
../.venv/bin/python report_graphs.py --experiment 740576277429403079 \
    --recorder 3a76e5cd5b8245cba963fea3ca876d1d --out renders

# 不存盘，直接在浏览器打开
../.venv/bin/python report_graphs.py --open
```

### 它做了什么

1. 扫描 `mlruns` 下所有实验，挑 `status == FINISHED` 且同时有 `pred.pkl`、`label.pkl` 的最新一次运行
2. 读 `pred.pkl` + `label.pkl`，拼成 `pred_label` 并改好列名
3. 依次调用 `model_performance_graph`（4 组）、`score_ic_graph`
4. 如果该 run 跑过回测，再调用 `report_graph` 和 `risk_analysis_graph`
5. 输出 14 个 html：`model_performance_0..6`、`score_ic`、`report`、`risk_analysis_0..4`

### 注意事项

- **输出目录不在 `.gitignore` 里**（仓库只忽略了 `mlruns/`），`renders/` 里的文件会出现在 `git status`。不需要提交就别 `git add`。
- 日志里会有一堆 `FutureWarning`（mlflow 文件后端、pandas groupby 行为），**都不影响出图**。
- `Gym has been unmaintained...` 是 qlib 导入 RL 模块时的无害提示。

## 速查：我要看 X，用哪个

| 我想知道 | 用 |
|---|---|
| 分数能不能区分股票好坏 | `model_performance_graph` → Cumulative Return |
| IC 稳不稳定 | `model_performance_graph` → IC / Monthly IC；或 `score_ic_graph` |
| 预测是不是天天变（换手高不高） | `model_performance_graph` → Auto Correlation / Turnover |
| 到底赚没赚钱 | `report_graph` |
| 成本吃了多少 | `report_graph` 里含成本/不含成本两条线的缺口 |
| 回撤在哪里发生 | `report_graph` 的阴影区、`risk_analysis_graph` 的月度回撤 |
| 收益靠买还是靠卖 | `cumulative_return_graph` |
| 买的股票是不是真的强 | `rank_label_graph` |
| 多次实验哪次最好 | MLflow UI |
| 每次训练的内部过程 | TensorBoard（仅 TRA / RL） |

## 常见错误对照

| 报错 | 原因 | 解决 |
|---|---|---|
| `KeyError: 'label'` | 列名还是 `LABEL0` | `pred_label.columns = ["label", "score"]` |
| `No valid experiment has been found` | 不在 `examples/` 目录下运行 | `cd examples` |
| `ModuleNotFoundError: plotly` | 没装 analysis 依赖 | `.venv/bin/pip install "plotly<7" statsmodels` |
| `command not found: mlflow` | 用了系统 PATH | 用 `.venv/bin/mlflow` |
| `ValueError: Unsupported graph name` | `graph_names` 传了未注册的名字 | 只用那四个内置名字 |
| 加载 position 报错 | 受限 unpickler 拦截 | `load_object(..., trusted=True)` |
