# 09 参数实验方案：感受每个旋钮的作用

这份方案把 `my_first_run.yaml` 复制成 13 个**单变量**配置，放在 `examples/param_exps/` 下。每次只改一处，跑完后用脚本并排对比，就能看出每个参数的实际影响。

> 基线就是你已跑通的 `my_first_run.yaml`（LGBModel + Alpha158 + csi300，IC 0.0468）。

---

## 一、怎么跑

进入 `examples/param_exps/`：

```bash
cd examples/param_exps
chmod +x run_all.sh
```

**先跑 3 个耗时短的，感受一下**（约 12 分钟）：

```bash
./run_all.sh 03 08 07
```

**跑全部 13 个**（约 50 分钟，可以放后台）：

```bash
./run_all.sh
```

**只跑某几个**（编号前缀）：

```bash
./run_all.sh 01 02 11
```

每个实验的完整日志在 `param_exps/<配置名>.log`。

跑完后对比：

```bash
cd .. && ../.venv/bin/python param_exps/compare.py
```

## 二、13 个对照组

### 学习率（最值得先看）

| 配置 | 改动 | 预期 |
|---|---|---|
| `01_lr_050` | `learning_rate: 0.2 → 0.05` | 步子变小、能走更多轮，通常 IC 上升 |
| `02_lr_010` | `learning_rate: 0.2 → 0.01` | 更慢，但可能欠拟合 |

**背景**：你的基线学习率 0.2 很高，配合早停在第 18 轮就停了。降低学习率一般能让模型找到更平滑的解。

### 树容量

| 配置 | 改动 | 预期 |
|---|---|---|
| `03_tree_small` | `max_depth 8→5`，`num_leaves 210→63` | 模型更简单，抗过拟合，但可能欠拟合 |
| `04_tree_large` | `max_depth 8→12`，`num_leaves 210→511` | 容量更大，可能过拟合，训练变慢 |

看 `train's l2` 和 `valid's l2` 的差距：差距大 = 过拟合。

### 正则化

| 配置 | 改动 | 预期 |
|---|---|---|
| `05_regularize_strong` | `lambda_l1 205→800`，`lambda_l2 580→2000` | 更强约束，特征用得更少 |
| `06_regularize_weak` | `lambda_l1 205→50`，`lambda_l2 580→100` | 约束放松，可能过拟合 |

### 训练过程

| 配置 | 改动 | 预期 |
|---|---|---|
| `07_es_100` | `early_stopping_rounds: 50 → 100` | 更容易找到更晚的最优点，但训练更久 |

你基线的日志里有：

```
Early stopping, best iteration is:
[18] train's l2: 0.982182  valid's l2: 0.993497
```

第 18 轮就停了。这个实验直接测「是不是停得太早」。

> **已实测（本机验证）：结论是否定的。**
>
> 把早停阈值放到 100 后，训练确实跑满 100 轮，但验证集损失一路变差：
>
> | 轮数 | train's l2 | valid's l2 |
> |---|---|---|
> | 18（最优） | 0.982182 | **0.993497** |
> | 20 | 0.981377 | 0.993566 |
> | 40 | 0.973719 | 0.993846 |
> | 60 | 0.966980 | 0.994660 |
> | 100 | 0.955041 | 0.995790 |
>
> train 损失持续下降、valid 损失持续上升，是**教科书式的过拟合**。最优轮数确实是 18，放宽早停只会让模型记住更多噪声。最终 IC 与基线完全一致（0.0468）。
>
> **这条结论的价值**：说明「模型训练不充分」这个假设不成立，提升空间不在训练轮数上，要去动标签、特征或数据。

### 组合与数据（不是模型参数，但影响很大）

| 配置 | 改动 | 预期 |
|---|---|---|
| `08_topk_30` | `topk: 50 → 30` | 更集中，超额弹性大，回撤更明显 |
| `09_csi500` | 股票池 `csi300 → csi500`，基准换 `SH000905` | IC 可能降、年化可能升 |
| `10_alpha360` | 特征集 `Alpha158 → Alpha360` | 树模型通常会变差 |
| `11_label_5d` | 标签改 5 日收益 | **已验证**：IC 0.0468 → 0.0690 |

### 交互效应

| 配置 | 改动 | 目的 |
|---|---|---|
| `12_lr005_small` | `learning_rate 0.05` + `max_depth 5` + `num_leaves 63` | 两处改动，看「小学习率 + 小树」是否互补 |

> 这一个故意改了两处，是唯一违反「单变量」原则的配置，专门用来看交互效应。单独分析它时不能归因到某一个参数。

## 三、看结果时注意什么

### 1. 先看 IC，再看年化

`compare.py` 输出的前三列是 IC / ICIR / Rank IC——这是**模型能力**。

计成本超额年化受回测影响更大，波动也更大。**如果 IC 没变而年化变了，多半是回测或组合层的偶然。**

### 2. 看 `train's l2` 与 `valid's l2` 的差距

打开任意一个 `.log`，搜索 `Early stopping` 前面的几行：

```
[20] train's l2: 0.981377  valid's l2: 0.993566
```

- 两者接近 → 没怎么过拟合，但可能欠拟合
- train 明显低于 valid → 过拟合
- 两者都很高且不再下降 → 欠拟合，该加容量或加特征

### 3. 看最优轮数

```
grep "best iteration" -A1 param_exps/01_lr_050.log
```

学习率降低后，最优轮数应该明显增加。如果还是十几轮就停，说明**问题不在学习率，而在特征或标签**。

### 4. 单次结果不可信

每个配置只跑一次，IC 的随机波动大约在 ±0.003 量级。**差距小于 0.003 的不要下结论。** 想确认有效，把那一项跑 5 次看均值。

## 四、推荐的观察顺序

| 顺序 | 配置 | 想回答的问题 |
|---|---|---|
| 1 | `07_es_100` | 早停是不是停太早了？ |
| 2 | `01_lr_050` | 学习率降下来有没有用？ |
| 3 | `03_tree_small` / `04_tree_large` | 模型是太复杂还是太简单？ |
| 4 | `05` / `06` | 正则化该加还是该减？ |
| 5 | `08_topk_30` | 持仓集中度怎么影响收益曲线？ |
| 6 | `09` / `10` / `11` | 换数据、换特征、换标签 |

**核心原则仍然是一次只改一个变量。** 想组合两个有效参数，回到基线配置再单独建一个组合实验。

## 六、常见问题

**Q：能不能同时开多个实验加速？**
不建议。每个实验峰值约 1.5GB 内存，加上 LightGBM 线程，这台 16G 机器同时跑两个容易触发 swap，反而更慢。串行跑。

**Q：中途想停？**
Ctrl-C 即可。已完成的实验结果都在 mlruns 里，不会丢。

**Q：想加自己的参数？**
复制 `00_baseline.yaml`，改一处，按编号命名。`compare.py` 会自动发现新的配置（它按 `cmd-sys.argv` 里的文件名识别）。

**Q：为什么有些配置没出现在对比表里？**
`compare.py` 只显示状态为 `FINISHED` 的 run。失败了看对应的 `.log`。
