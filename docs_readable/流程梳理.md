# 一、"训练模型"是什么意思？跟大语言模型有关系吗？

## 完全没有关系

虽然都叫"训练模型"，但这是**两个完全不同的东西**：

| | LLM（ChatGPT 这类） | Qlib 里的模型 |
|---|---|---|
| 模型类型 | 神经网络（Transformer） | **LightGBM = 决策树集成** |
| 参数量 | 几千亿 | 几万到几十万 |
| 训练数据 | 几万亿 token 文本 | **170 万行数字表格** |
| 输入 | 文字序列 | **158 个数字** |
| 输出 | 下一个 token 的概率 | **1 个数字（收益率预测）** |
| 训练时间 | 几个月 + 上千张 GPU | **1 分钟 + 一个 CPU 核** |
| 训练目标 | 预测下一个词 | 预测股票涨跌 |

**LightGBM 不懂语言、不懂语义、没有任何"理解"能力。它就是一个函数拟合器。**

## 训练到底在做什么（用最直白的话）

训练 = **找一条曲线，让"158 个因子"尽可能准确地映射到"未来收益率"**。

具体做法是**梯度提升决策树**：

```
第 1 步：用训练数据建第一棵树
    树的结构是从数据里自动"切"出来的，例如：
    "如果 MA5 > 1.02 且 STD20 < 0.03，则预测收益 = +0.8%"

第 2 步：算每行数据的"预测误差"（残差）
    真实收益 1.2%，第一棵树预测 0.8%，残差 = +0.4%

第 3 步：再建一棵树，专门拟合这个残差
    "如果 RSV5 > 0.8 且 VOLUME 上升，则修正 +0.3%"

第 4 步：重复 1000 次

最终预测 = 第1棵树的输出 + 第2棵树的输出 + ... + 第1000棵树的输出
```

**关键点：这些"如果...则..."规则不是人写的，是算法从 170 万行数据里自动搜出来的。**

## 代码就三行

[qlib/contrib/model/gbdt.py:77](qlib/contrib/model/gbdt.py:77)：

```python
self.model = lgb.train(
    self.params,        # 超参：树多深、学多快、正则多强
    ds[0],              # 训练数据（170万行 × 158列 + 1列标签）
    num_boost_round=1000,
    valid_sets=ds,      # 验证数据，用来早停
)
```

**整个"训练"就是调用 `lgb.train()` 这一个函数。** 没有神经网络、没有反向传播、没有 GPU、没有 token。

# 二、加载的数据具体是什么

这是最关键的问题。**数据最终变成一个二维表格。**

## 实际长这样

```
                          feature(158列)                              label
instrument  datetime      KMID    KLEN   ...  ROC60   MA5    ...      LABEL0
SH600000    2008-01-02    0.0103  0.0521 ...  -0.031  1.024  ...       0.0042
SH600000    2008-01-03   -0.0081  0.0410 ...   0.017  1.011  ...      -0.0021
SH600004    2008-01-02    0.0231  0.0712 ...   0.042  0.988  ...       0.0121
...
```

**每一行 = 一只股票在某一天**

**每一列的含义：**

| 列 | 内容 | 举例 |
|---|---|---|
| 前 158 列 | 因子（feature） | `MA5 = 1.024` 表示"5日均线比今天收盘价高 2.4%" |
| 最后 1 列 | 标签（label） | `0.0042` 表示"T+1 到 T+2 涨了 0.42%" |

## 规模

```python
train 段 2008-01-01 ~ 2014-12-31
    ≈ 1700 个交易日 × 约 1000 行/天  ≈ 170 万行

每行 158 个因子 + 1 个标签 = 159 个数字
```

**所以训练数据是 170 万 × 159 个浮点数 ≈ 1.3 GB 的表格。**

## 因子和标签的区别（这是你问题的核心）

| | 因子（feature） | 标签（label） |
|---|---|---|
| 是什么 | **今天能知道的**信息 | **未来才发生的**结果 |
| 例子 | 今天的收盘价、5日均线、成交量占比 | T+1 到 T+2 的涨跌幅 |
| 能否用未来数据 | **绝对不能** | 本身就是未来数据 |
| 有多少 | 158 个 | 1 个 |
| 谁定义 | `Alpha158.get_feature_config()` | `Alpha158.get_label_config()` |

**因子的本质是"把今天能看到的所有信息，压缩成 158 个数字"。**

**标签的本质是"事后答案"。**

模型训练就是在找：`158 个因子 → 标签` 这个映射关系。

## 为什么会有 158 个因子

因为**原始数据只有 5 个字段**（open/high/low/close/volume），信息量太少。要变成 158 个，靠的是**变换**：

```
原始：close = 10.5

变换出：
  MA5      = Mean($close, 5)/$close          = 1.024
  STD20    = Std($close, 20)/$close          = 0.031
  ROC60    = Ref($close, 60)/$close          = 0.87
  RSV5     = ($close-Min($low,5))/(...)      = 0.92
  KLEN     = ($high-$low)/$open              = 0.045
  ...
```

**这就是"因子工程"——把 1 个价格变成 158 个不同角度的描述。**

# 三、怎么接入自己的数据

有**三个层次**，取决于你想要什么。

## 层次 1：你自己的行情数据（OHLCV）

**场景**：你有自己的数据库/CSV，想替换掉 `~/.qlib/qlib_data/cn_data`。

**做法**：转成 qlib 的 `.bin` 格式。

```bash
python scripts/dump_bin.py dump_all \
    --data_path ~/my_data \
    --qlib_dir ~/.qlib/qlib_data/my_data \
    --include_fields open,close,high,low,volume,factor \
    --file_suffix .csv \
    --date_field_name date \
    --symbol_field_name symbol
```

**你的 CSV 必须长这样**：

```
symbol,date,open,close,high,low,volume,factor
SH600000,2020-11-01,120,121,123,119,12300000,1.0
SH600000,2020-11-02,121,123,124,120,11200000,1.0
```

**或者每只股票一个文件**：`SH600000.csv`（文件名就是代码）。

**转完之后改 YAML**：

```yaml
qlib_init:
    provider_uri: "~/.qlib/qlib_data/my_data"   # 改成你的
    region: cn
```

**这样 Alpha158 的 158 个因子会从你的数据里重新算出来。**

## 层次 2：你自己的因子（已经算好的）

**场景**：你不想用 `D.features()` 算，而是已经有了一张因子表（比如用 pandas 算好的、从别的系统导出的、或者买的因子库）。

**用途**：`StaticDataLoader`——直接加载现成的 DataFrame。

```python
import pandas as pd
from qlib.data.dataset.loader import StaticDataLoader

# 你的因子表，MultiIndex = (datetime, instrument)
df = pd.read_parquet("my_factors.parquet")
#                     feature                    label
# datetime   instrument   alpha1  alpha2  ...    LABEL0
# 2020-01-02 SH600000      0.23   -1.05  ...     0.0042

loader = StaticDataLoader(config={"feature": my_feature_df,
                                  "label":   my_label_df})
handler = DataHandlerLP(instruments="csi300",
                        start_time="2015-01-01", end_time="2020-08-01",
                        data_loader=loader, ...)
```

**关键：`StaticDataLoader` 的 `config` 可以接受 `dict[str, DataFrame]`**（[loader.py:274](qlib/data/dataset/loader.py:274)）。

**这绕过了整个表达式引擎，你给什么它就用什么。**

## 层次 3：在 Alpha158 基础上加自己的因子

**场景**：你想保留 Alpha158 的 158 个，再加 5 个自己的。

**做法**：继承 `Alpha158`，覆写 `get_feature_config()`：

```python
from qlib.contrib.data.handler import Alpha158
from qlib.contrib.data.loader import Alpha158DL

class MyAlpha(Alpha158):
    def get_feature_config(self):
        # 拿到 Alpha158 的原始配置
        base_fields, base_names = Alpha158DL.get_feature_config()

        # 加自己的因子（用表达式语法）
        my_fields = [
            "Corr($close, Log($volume+1), 20)",       # 20日价量相关
            "Std($close, 10)/Mean($close, 10)",        # 10日变异系数
            "Ref($volume, 1)/($volume+1e-12)",         # 昨日量比
        ]
        my_names = ["MY_CORR20", "MY_CV10", "MY_VOLRATIO"]

        return base_fields + my_fields, base_names + my_names
```

然后在 YAML 里：

```yaml
handler:
    class: MyAlpha
    module_path: my_project.handlers    # 你放这个类的模块路径
    kwargs: *data_handler_config
```

## 层次 4：你自己的标签

**场景**：你不想预测 T+1→T+2，想预测 5 日收益、或者分类（涨/跌）。

```python
class MyAlpha(Alpha158):
    def get_label_config(self):
        # 5日后的收益
        return ["Ref($close, -6)/Ref($close, -1) - 1"], ["LABEL0"]

        # 或者：二分类（未来5天涨>2% 记 1）
        # return ["Greater(Ref($close,-6)/Ref($close,-1)-1, 0.02)"], ["LABEL0"]
```

# 四、"这个数据是因子和策略吗"——不是

你的问题里有个概念需要澄清。这三个东西是**完全不同**的层次：

```
数据  →  因子  →  模型  →  策略  →  回测
 │        │        │        │
 │        │        │        └─ 决定"买哪些、买多少、多久换"
 │        │        └────────── 决定"158个因子 → 一个分数"
 │        └─────────────────── 决定"用什么数字描述股票"
 └──────────────────────────── 决定"原始的价量数据从哪来"
```

具体到我们跑的那次：

| 概念 | 具体是什么 | 在哪配置 |
|---|---|---|
| **数据** | A股 OHLCV（open/close/high/low/volume/factor） | `qlib_init.provider_uri` |
| **因子** | Alpha158 的 158 个表达式 | `handler.class: Alpha158` |
| **标签** | `Ref($close,-2)/Ref($close,-1)-1` | 同上 |
| **模型** | LightGBM | `task.model` |
| **策略** | TopkDropout：每天买分数最高的 50 只，最多换 5 只 | `port_analysis_config.strategy` |
| **回测** | Exchange 撮合 + 手续费 + 涨跌停 | `port_analysis_config.backtest` |

**所以"数据"不等于"因子"**：

- **数据**是原始的（10.5 元、100 万股）
- **因子**是从数据算出来的（MA5=1.024、RSV=0.92）
- **策略**是**在模型输出之后的**决策逻辑（买哪 50 只）

## 三者可以互相独立替换

这正是 Qlib 的设计目的：

| 你想改什么 | 改哪里 | 其他部分要动吗 |
|---|---|---|
| 换数据源 | `provider_uri` | 不用 |
| 换因子 | `handler.class` | 不用 |
| 换模型 | `task.model.class` | 不用 |
| 换策略 | `strategy.class` | 不用 |
| 换回测参数 | `backtest.exchange_kwargs` | 不用 |

# 五、一个完整例子：用你自己的数据跑一次

假设你有一个自己的因子表 `my_factors.parquet`：

```python
import pandas as pd, qlib
qlib.init(provider_uri="~/.qlib/qlib_data/cn_data", region="cn", kernels=1)

from qlib.data.dataset.loader import StaticDataLoader
from qlib.data.dataset.handler import DataHandlerLP
from qlib.data.dataset import DatasetH
from qlib.contrib.model.gbdt import LGBModel
from qlib.contrib.strategy import TopkDropoutStrategy

# 你的因子（MultiIndex: datetime, instrument）
features = pd.read_parquet("my_factors.parquet")   # 列名随意
labels   = pd.read_parquet("my_labels.parquet")    # 单列

loader = StaticDataLoader(config={"feature": features, "label": labels})

handler = DataHandlerLP(
    instruments="csi300",
    start_time="2015-01-01", end_time="2020-08-01",
    data_loader=loader,
    learn_processors=[{"class": "DropnaLabel"}],
    infer_processors=[{"class": "Fillna", "kwargs": {"fill_value": 0}}],
)

dataset = DatasetH(handler=handler, segments={
    "train": ("2015-01-01", "2018-12-31"),
    "test":  ("2019-01-01", "2020-08-01"),
})

model = LGBModel(loss="mse", num_threads=2)
model.fit(dataset)
pred = model.predict(dataset, "test")
```

**注意：整个过程没有用到表达式引擎、没有 `$close`、没有 Alpha158。你给什么 DataFrame 它就用什么。**

# 六、回到你最初的问题

你的困惑可能来自**"训练"这个词在两边含义不同**：

- **LLM 的训练**：让模型学会语言规律，需要海量数据和算力
- **Qlib 的训练**：**在 158 维空间里找一个分类边界**，本质是统计拟合

**你可以把 Qlib 的"训练"理解成 Excel 里的"回归分析"放大版**——输入一堆列，输出一个预测值，算法自动找公式。

它唯一的"智能"在于：**能自动从 170 万行里发现人眼看不到的 158 维交互模式**。但它不理解股票、不理解公司、不理解经济——它只是在拟合数字。
