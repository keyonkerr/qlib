# 02 快速开始：跑通官方示例

本文带你从零跑通官方 LightGBM + Alpha158 示例（macOS 实测），并解释每一步在做什么、产出什么。

> 全部数字来自本机 2026-11-13 的实际运行，实验 ID `740576277429403079`。

## 一、环境准备

### 1. 创建虚拟环境

qlib 官方 `pyproject.toml` 声明支持 Python 3.8~3.12。**Python 3.13 有风险**，建议用 3.11：

```bash
cd /Users/k/workspace/qlib
/opt/homebrew/bin/python3.11 -m venv .venv
.venv/bin/python -m pip install -q --upgrade pip setuptools wheel setuptools_scm cython numpy
```

### 2. 安装 qlib（editable）

```bash
.venv/bin/python -m pip install -e .
```

这一步会**编译 Cython 扩展**（`rolling` 和 `expanding`），需要 3~5 分钟。装完后 `qlib/data/_libs/` 下会出现 `.so` 文件——**删掉会导致 import 失败**。

### 3. 验证

```bash
.venv/bin/python -c "
import qlib
from qlib.data._libs import rolling, expanding
import lightgbm
print('qlib', qlib.__version__)
print('lightgbm', lightgbm.__version__)
print('cython libs OK')
"
```

预期输出：

```
qlib 0.1.dev2071
lightgbm 4.7.0
cython libs OK
```

### 4. 下载数据

```bash
.venv/bin/python scripts/get_data.py qlib_data --target_dir ~/.qlib/qlib_data/cn_data --region cn
```

约 510MB，几分钟。完成后验证：

```bash
ls ~/.qlib/qlib_data/cn_data/calendars   # 应有 day.txt
ls ~/.qlib/qlib_data/cn_data/instruments # 应有 csi300.txt / csi500.txt / all.txt
ls ~/.qlib/qlib_data/cn_data/features | wc -l   # 应有 3875
```

## 二、配置文件

示例配置在 [examples/my_first_run.yaml](../examples/my_first_run.yaml)。

```yaml
qlib_init:
    provider_uri: "~/.qlib/qlib_data/cn_data"
    region: cn
    kernels: 1                  # 单进程（见下方「为什么」）

market: &market csi300
benchmark: &benchmark SH000300

data_handler_config: &data_handler_config
    start_time: 2008-01-01
    end_time: 2020-08-01
    fit_start_time: 2008-01-01
    fit_end_time: 2014-12-31
    instruments: *market

task:
    model:
        class: LGBModel
        module_path: qlib.contrib.model.gbdt
        kwargs:
            loss: mse
            learning_rate: 0.2
            max_depth: 8
            num_leaves: 210
            lambda_l1: 205.6999
            lambda_l2: 580.9768
            num_threads: 2
    dataset:
        class: DatasetH
        module_path: qlib.data.dataset
        kwargs:
            handler:
                class: Alpha158
                module_path: qlib.contrib.data.handler
                kwargs: *data_handler_config
            segments:
                train: [2008-01-01, 2014-12-31]
                valid: [2015-01-01, 2016-12-31]
                test: [2017-01-01, 2020-08-01]
    record:
        - class: SignalRecord
        - class: SigAnaRecord
        - class: PortAnaRecord
```

### `&` 和 `*` 是什么

YAML 的**锚点**和**引用**：

```yaml
market: &market csi300     # 定义锚点
instruments: *market       # 引用，展开成 csi300
```

好处：改一处，所有引用同步变。做对照实验极方便。

### 为什么 `kernels: 1`

qlib 默认并行度是 `CPU核数 - 2`。24 核机器会有 22 个 worker 进程。

在 **Windows** 上这会灾难性卡死：

1. Windows 没有 `fork`，joblib 用 `spawn`
2. `spawn` 会重新 import 主脚本
3. 没有 `if __name__ == "__main__":` 守卫 → 每个子进程重新执行整个脚本
4. 子进程再 spawn 22 个孙进程 → 指数爆炸

**三条铁律**：`kernels: 1` + `if __name__ == "__main__":` + 不在仓库根目录跑。

> `kernels: 0` **不能用**，joblib 会抛 `ValueError: n_jobs == 0 in Parallel has no meaning`。
>
> macOS/Linux 上 `fork` 可用，但单进程仍然更省内存，示例里保持 `kernels: 1`。

## 三、运行

```bash
cd examples
MLFLOW_ALLOW_FILE_STORE=true OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 ../.venv/bin/python -m qlib.cli.run my_first_run.yaml
```

**为什么要 `MLFLOW_ALLOW_FILE_STORE=true`**：qlib 用 MLflow 记录实验到 `./mlruns/`。新版 MLflow 认为文件后端进入维护模式，默认会警告。这个环境变量是官方给的开关（本仓库 pin 了 `mlflow<3.13`，不设也能跑）。

**为什么用 `python -m qlib.cli.run` 而不是 `qrun`**：`qrun` 是脚本入口，在某些 shell 环境（如 Git Bash）下路径解析会出问题。`python -m` 更可靠。

## 六、流程内部：每一步在做什么

`qrun` 内部执行 [qlib/model/trainer.py:44](../qlib/model/trainer.py) 的 `_exe_task`。

### ① 初始化

```python
qlib.init(provider_uri="~/.qlib/qlib_data/cn_data", region="cn", kernels=1)
```

设置全局配置对象 `C`，清空内存缓存 `H`，校验数据路径。

### ② 构造 Dataset（耗时最长）

```python
dataset = init_instance_by_config(task_config["dataset"])
```

内部三步：

**(a) 构造 Alpha158 Handler**

生成 158 个因子表达式（[qlib/contrib/data/loader.py](../qlib/contrib/data/loader.py)）：

| 类别 | 数量 | 例子 |
|---|---|---|
| kbar | 9 | `($close-$open)/$open` |
| price | 4 | `$open/$close` |
| rolling × 5 窗口 | 145 | `Mean($close,5)/$close` |

标签：`Ref($close, -2)/Ref($close, -1) - 1`（**T+1 买入、T+2 卖出的收益**）

**(b) 加载原始数据**

对 csi300 每只股票，把 158 个表达式编译成算子树逐个算出。

产出：MultiIndex DataFrame

```
                        feature(158列)                  label
instrument  datetime    KMID  KLEN  ...  ROC60  ...    LABEL0
SH600000    2008-01-02  0.01  0.05  ...  -0.03  ...    0.0042
```

**(c) Processor 加工**

`DataHandlerLP` 有两条数据流（[qlib/data/dataset/handler.py:570](../qlib/data/dataset/handler.py)）：

```
原始数据 → shared_processors → infer_processors → _infer（推理用）
                            ↘                    → learn_processors → _learn（训练用）
```

**⚠️ Alpha158 的 `infer_processors` 默认是 `[]`**，只有 learn 流的 `DropnaLabel` 和 `CSZScoreNorm` 生效。详见 [模型篇](05-模型篇.md#第-4-层数据加工processor)。

**(d) DatasetH 切分**

```python
DatasetH(handler=handler, segments={
    "train": ("2008-01-01", "2014-12-31"),
    "valid": ("2015-01-01", "2016-12-31"),
    "test":  ("2017-01-01", "2020-08-01"),
})
```

只是按时间取切片，不复制数据。

### ③ 训练模型

```python
model = LGBModel(loss="mse", max_depth=8, num_leaves=210, ...)
model.fit(dataset)
```

`LGBModel.fit` 内部（[qlib/contrib/model/gbdt.py:25](../qlib/contrib/model/gbdt.py)）：

```python
df = dataset.prepare("train", col_set=["feature","label"], data_key=DataHandlerLP.DK_L)
x, y = df["feature"], df["label"]
lgb.train(params, lgb.Dataset(x.values, label=y), ...)
```

**注意 `DK_L`**：训练用 learn 数据（含 `CSZScoreNorm` 截面标准化）。**推理时** `predict` 用 `DK_I`（infer 数据）。

### ④ Record 三连

`fill_placeholder` 先替换占位符：

```python
placehorder_value = {"<MODEL>": model, "<DATASET>": dataset}
```

然后按顺序执行：

**`SignalRecord`** — 存预测

```python
pred = model.predict(dataset)           # test 段预测
self.save(**{"pred.pkl": pred})
raw_label = dataset.prepare("test", col_set="label", data_key=DK_R)  # 原始标签
self.save(**{"label.pkl": raw_label})
```

**为什么要原始标签**：算 IC 时预测和标签必须同尺度，标签被 z-score 过会让 IC 失真。

**`SigAnaRecord`** — 算 IC

```python
pred = self.load("pred.pkl")
label = self.load("label.pkl")
ic, ric = calc_ic(pred, label)
metrics = {
    "IC": ic.mean(), "ICIR": ic.mean()/ic.std(),
    "Rank IC": ric.mean(), "Rank ICIR": ric.mean()/ric.std(),
}
```

`calc_ic`（[qlib/contrib/eva/alpha.py:160](../qlib/contrib/eva/alpha.py)）**逐日算截面相关系数**再取均值。

**`PortAnaRecord`** — 回测

```python
strategy = TopkDropoutStrategy(signal=<PRED>, topk=50, n_drop=5)
backtest(strategy, start="2017-01-01", end="2020-08-01", benchmark="SH000300")
```

`TopkDropoutStrategy` 每天：给所有股票打分 → 目标持有 topk=50 → 每天最多换 n_drop=5 只。

**为什么限制 n_drop**：不限制的话每天全换仓，手续费吃光收益。

撮合检查：

| 检查 | 参数 |
|---|---|
| 涨跌停 | `limit_threshold: 0.095` |
| 手续费 | `open_cost 5bp / close_cost 15bp` |
| 最低费 | `min_cost: 5` |

## 七、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `ValueError: n_jobs == 0` | `kernels: 0` | 改 `kernels: 1` |
| `MlflowException: filesystem tracking backend ... maintenance mode` | 新版 MLflow | `MLFLOW_ALLOW_FILE_STORE=true` |
| `ModuleNotFoundError: qlib.data._libs.rolling` | Cython 未编译 | `pip install -e .` 重装 |
| 进程爆炸 / 卡死 | `kernels` 太大 + 缺 `__main__` 守卫 | `kernels: 1` + 加守卫 |
| 内存持续增长 | 数据全量载入内存 | 缩小时间区间或股票池 |
| 找不到 `python3.13` 的包 | Python 版本过高 | 用 3.11 |

## 八、下一步：做对照实验

复制配置，改一个变量，跑一次，对比结果：

```bash
cp examples/my_first_run.yaml examples/exp_csi500.yaml
# 把 market: &market csi300 改成 csi500
# 把 benchmark: &benchmark SH000300 改成 SH000905
```

建议的对照序列：

| 实验 | 改动 | 预期观察 |
|---|---|---|
| 1 | 基线 | IC ≈ 0.047 |
| 2 | csi300 → csi500 | IC 略降，但年化可能更高 |
| 3 | `n_drop: 5` → `2` | 成本下降，信号捕获变差 |
| 4 | Alpha158 → Alpha360 | LightGBM 的 IC 会降（见 [模型篇](05-模型篇.md)） |
| 5 | `learning_rate: 0.2` → `0.05` | 通常 IC 略升，训练变慢 |
| 6 | LightGBM → DoubleEnsemble | IC 提升约 16% |

跑多次看分布（模型有随机性）：

```bash
cd examples && python run_all_model.py run 20 lightgbm Alpha158 csi300
```

每次跑完对比 `mlruns/` 里的 metrics。各指标含义见 [指标篇](07-指标篇.md)。
