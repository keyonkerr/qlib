# 06 回测篇：把预测分数变成真金白银

这份文档解释 qlib 里回测这一步的作用、内部流程，以及怎么读它的输出。所有数字和代码路径都来自本机实际跑通的官方示例（LightGBM + Alpha158 + csi300，2017-01-03 ~ 2020-07-31，871 个交易日）。

> 本文讲回测**在模拟什么、每天发生什么、结果怎么用**。每个指标的完整定义与好坏判断见 [指标篇](07-指标篇.md)。

---

## 一、为什么必须有回测

跑到 `④ SignalRecord` 结束时，你手上只有一张表：

```
                         score
datetime   instrument
2017-01-03 SH600000     -0.027139
           SH600008      0.007010
           ...
```

这张表说的是"模型认为明天谁涨得多"。但**分数本身赚不到钱**。要变成钱，必须回答一串交易决策问题：

| 问题 | 不回答会怎样 |
|---|---|
| 买哪几只？ | 300 只全买 = 变成指数，超额归零 |
| 每只买多少？ | 随意分配会引入额外风险 |
| 什么时候换？ | 天天全换，手续费吃光收益 |
| 买不到怎么办？ | 涨停板买不进，模拟结果虚高 |
| 手续费多少？ | 忽略成本，年化虚高 4~5 个点（见本次实测） |

**回测就是把"预测 → 交易规则 → 账户曲线"这条链条完整模拟一遍。**

没有回测，IC = 0.047 只说明"相关性还行"；
有了回测，才能说"扣完成本年化超额 8.07%"。

## 二、它在整条流水线里的位置

```
② 构造 Dataset    →  158 列因子表
③ 训练模型        →  LGBModel（params.pkl）
④ SignalRecord    →  pred.pkl（只有分数，不能赚钱）
④ SigAnaRecord    →  IC / Rank IC（衡量分数好坏，仍然不涉及交易）
⑤ PortAnaRecord   →  回测：分数 + 交易规则 → 账户曲线   ← 本文
```

对应配置里 `record` 列表的第三项：

```yaml
record:
    - class: SignalRecord
    - class: SigAnaRecord
    - class: PortAnaRecord          # ← 这一项触发回测
      module_path: qlib.workflow.record_temp
      kwargs:
        config: *port_analysis_config
```

`PortAnaRecord` 的实现在 `qlib/workflow/record_temp.py:365`。

## 三、回测到底在模拟什么

### 3.1 配置拆成两半

```yaml
port_analysis_config: &port_analysis_config
    strategy:                        # 决策层：买什么、卖什么
        class: TopkDropoutStrategy
        module_path: qlib.contrib.strategy
        kwargs:
            signal: <PRED>           # 用 pred.pkl 的分数
            topk: 50                 # 目标持仓 50 只
            n_drop: 5                # 每天最多换 5 只
    backtest:                        # 执行层：市场规则 + 成本
        start_time: 2017-01-01
        end_time: 2020-08-01
        account: 100000000          # 1 亿本金
        benchmark: SH000300
        exchange_kwargs:
            limit_threshold: 0.095  # 涨跌停 ±9.5% 不可成交
            deal_price: close       # 按收盘价成交
            open_cost: 0.0005       # 买入 5bp
            close_cost: 0.0015      # 卖出 15bp
            min_cost: 5             # 每笔最低 5 元
```

- **strategy** 回答"该做什么交易"——纯逻辑，不涉及钱
- **backtest** 回答"这些交易能不能成交、成交后账户变成多少"——市场现实

这个划分是有意的：换个策略不用重写市场规则，换个市场不用重写策略。

### 3.2 每一个交易日发生的事

`TopkDropoutStrategy` 的实现在 `qlib/contrib/strategy/signal_strategy.py:74`，每日循环：

**第 1 步：排序**

```python
# 持仓中的股票按今天的预测分数重新排序（signal_strategy.py:196）
last = pred_score.reindex(current_stock_list).sort_values(ascending=False).index
```

**第 2 步：决定卖谁**

```python
# 持仓分数最低的 n_drop 只（signal_strategy.py:222）
sell = last[last.isin(get_last_n(comb, self.n_drop))]
```

同时有个保护：会把"新买入候选"和"当前持仓"合并后统一排序，**避免卖掉高分股去买低分股**——注释里明确写了这个意图。

**第 3 步：决定买谁**

```python
# 持仓池之外，分数最高的 n_drop 只（signal_strategy.py:201）
today = get_first_n(pred_score[~pred_score.index.isin(last)].sort_values(...).index, ...)
```

**第 4 步：撮合检查**

对每个卖单/买单，`Exchange` 逐笔检查：

| 检查 | 参数 | 代码位置 |
|---|---|---|
| 是否停牌 | — | `is_stock_tradable` |
| 是否涨跌停 | `limit_threshold: 0.095` | `check_order` |
| 卖出股数 | 全部持仓 | `get_stock_amount` |
| 买入金额 | `cash × risk_degree / len(buy)` | `signal_strategy.py:270` |

注意 `risk_degree` 默认 **0.95**（`signal_strategy.py:31`）——始终留 5% 现金，不梭哈。

**第 5 步：成交记账**

```python
trade_val, trade_cost, trade_price = self.trade_exchange.deal_order(sell_order, position=current_temp)
cash += trade_val - trade_cost      # 卖出到手 = 成交额 - 成本
```

买入时按 `value / buy_price` 算股数，再扣 `open_cost`。

**第 6 步：收盘结算**

把所有持仓按当日收盘价估值 + 现金 = 当日总资产，写入 `report_normal_1day.pkl`。

871 天 × 上述六步 = 一次完整回测。

## 四、输出长什么样（本次实测数据）

### 4.1 账户曲线 `report_normal_1day.pkl`

| 日期 | return | bench | cost | turnover | account |
|---|---|---|---|---|---|
| 2017-01-03 | 0 | +0.97% | 0 | 0 | 100,000,000 |
| 2017-01-04 | 0 | +0.78% | 0.04% | **79.8%** | 99,960,100 |
| 2017-01-05 | +0.52% | -0.02% | 0.02% | 22.5% | 100,463,300 |
| 2017-01-06 | -0.32% | -0.60% | 0.02% | 20.1% | 100,124,200 |
| … | | | | | |
| 2020-07-31 | +0.86% | +0.84% | 0.02% | | **186,232,683** |

两个关键读法：

- **第 1 天换手 79.8%**：空仓建仓一次性买入 40+ 只，成本峰值
- **之后日均换手约 19%**：`n_drop=5` / 50 只 = 10% 换股，叠加权重再平衡后约 20%
- **`account` 期末 1.86 亿**：注意这是**含基准涨跌的绝对收益**，不是策略超额

列的含义：

| 列 | 含义 |
|---|---|
| `return` | 当日策略组合收益率（含持仓涨跌） |
| `bench` | 当日基准（沪深300）收益率 |
| `cost` | 当日交易成本（占账户比例） |
| `turnover` | 当日换手率（买卖金额 / 账户总值） |
| `account` | 当日收盘账户总资产 |
| `value` / `cash` | 持仓市值 / 现金 |

### 4.2 持仓明细 `positions_normal_1day.pkl`

```
2017-01-04  持仓股票 42 只,  现金 20,160,100,  总资产 99,960,100

SH600050  {'amount': 625,773.7, 'price': 3.0362, 'weight': 1.90%, 'count_day': 1}
SH601668  {'amount': 1,063,434.3, 'price': 1.7867, 'weight': 1.90%, 'count_day': 1}
SZ000725  {'amount': 2,827,054.8, 'price': 0.6721, 'weight': 1.90%, 'count_day': 1}
```

- 每只约 **1.90%** 仓位（50 只 ≈ 等权 2%，实际未买满）
- `count_day` 是连续持有天数，**这个字段能直接看出换手节奏**
- 建仓第一天持仓 42 只而非 50，因为部分股票涨停/停牌无法买入

### 4.3 绩效指标 —— 三组对比

```
benchmark return (1day)               ← 沪深300 基准
  annualized_return  0.113561             年化 11.36%
  information_ratio  0.598699             IR 0.60
  max_drawdown      -0.370479             2018 熊市，回撤 -37%

excess return without cost (1day)     ← 纯选股能力
  annualized_return  0.126029             年化 12.60%
  information_ratio  1.428574             IR 1.43

excess return with cost (1day)        ← 实盘能拿到的
  annualized_return  0.080654             年化 8.07%
  information_ratio  0.914486             IR 0.91
```

**三行的意义**：

| 行 | 含义 | 用途 |
|---|---|---|
| 第 1 行 | 什么都不做，买沪深300ETF | 基准线，判断是否值得做主动管理 |
| 第 2 行 | 模型的**纯选股能力** | 决定因子/模型的上限 |
| 第 3 行 | **实盘能拿到的** | 决定这个策略是否值得上 |

**关键看第 2→3 行的落差**：

```
12.60%  →  8.07%      损失 4.53 个点（-36%）
```

这 4.53 点 = 日均换手 19% × 双边成本。**这个落差告诉你：调参时换手率比模型精度更重要。**

如果只看第 2 行，你会严重高估策略。回测的核心价值之一就是把这个幻觉戳破。

### 4.4 执行质量指标 `indicator_analysis_1day.pkl`

```
      value
ffr    1.0      ← 成交率 100%
pa     0.0      ← 成交价无优势/劣势
pos    0.0      ← 有价格优势的成交占比为 0
```

日频 + 大盘股 + 收盘价撮合，这个组合**完全正常**：回测假设成交量无限、成交价就是收盘价，所以三个值必然是这个结果。它们在分钟级/高频回测里才有诊断价值。

> **每个指标的完整公式、源码位置、好坏判断，见 [指标篇](07-指标篇.md)。** 本节只讲回测产出了什么。

## 五、回测结果怎么用于研究决策

回测不是"跑完看个数字"，它是**实验台**。三种典型用法：

### 5.1 判断策略值不值得做

看两张表：

```
信号是否有效？  IC = 0.0468, Rank IC = 0.0490, ICIR = 0.38     → 有效
实盘收益够不够？ 计成本超额年化 8.07%, IR 0.91                → 可用
```

### 5.2 找成本敏感度（最容易被忽略的）

改一个参数，看第 2→3 行的落差怎么变：

| 实验 | 改动 | 观察 |
|---|---|---|
| 基线 | `n_drop: 5` | 落差 4.53 点 |
| 低换手 | `n_drop: 2` | 落差缩小，但信号捕获变差 |
| 高换手 | `n_drop: 10` | 信号更好，但成本吃掉更多 |

**结论方向**：如果低换手版本的计成本收益反而更高，说明原参数换手过度。

### 5.3 防止自欺（回测的第三种价值）

每个量化研究者都会给自己编故事。回测是唯一能戳破故事的地方：

- "我的 IC 有 0.05，肯定赚钱" → 回测：扣完成本只剩 3%
- "我的策略年化 30%" → 回测：那是**绝对收益**，超额只有 5%
- "模型很强" → 回测：换手 80%，全给券商打工

## 六、常见误解

| 误解 | 实际 |
|---|---|
| `account` 从 1 亿涨到 1.86 亿 = 策略赚了 86% | 这里含基准涨跌。**策略的超额只有 8.07% 年化**，看 `excess_return_with_cost` |
| `IC 高 = 回测好` | IC 只看排序质量，不看成本。IC 0.05 换成 8% 还是 3%，全看换手 |
| `ffr = 1.0 = 执行完美` | 日频回测假设成交量无限，这个 1.0 没有信息量 |
| `pa = 0 = 成交很差` | 只是说明回测里成交价 = 收盘价，是模型简化 |
| `回测收益可复现实盘` | 有前视偏差、幸存者偏差、冲击成本未建模三大鸿沟 |

## 八、一句话总结

**回测 = 把"模型预测"翻译成"真金白银"的唯一桥梁。**

它同时回答两个问题：
1. **策略能不能赚钱** —— 计成本超额 8.07%
2. **交易成本会拿走多少** —— 4.53 个百分点（36% 的超额被摩擦吃掉）

只看 IC 你会高估策略；只看绝对收益你会误判策略。**三组绩效表才是完整的答案。**
