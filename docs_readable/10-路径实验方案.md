# 10 路径实验方案：五条路径各改一处，看效果差多少

[08 提升路径](08-提升路径.md) 讲的是「有哪些路可以走」，[09 参数实验方案](09-参数实验方案.md) 讲的是「模型参数怎么调」。这份方案回答第三个问题：

> **五条路径（标签 / 因子 / 模型 / 组合策略 / 交易执行）各动一次，效果差多少？哪条路值得投入？**

设计原则只有一条：**每个实验相对基线只改一个逻辑点**，这样任何差异都能归因。

- 路径 ① ② ③ 改动标签、特征、模型 → 必须**重新训练**，用 `qrun` 跑配置文件
- 路径 ④ ⑤ 只改组合策略和交易执行 → **不用重新训练**，复用基线的预测产物 `pred.pkl`，只重跑回测（秒级到分钟级）

所有配置在 [examples/path_exps/](../examples/path_exps/)，与 `my_first_run.yaml` 同源（`kernels: 1`、`num_threads: 2` 的资源限制保留）。

---

## 一、先跑一次「冒烟测试」，确认环境能用

在 `examples/` 目录下，用最简单的线性模型验证整条链路（只要十几秒）：

```bash
cd examples
PYTHONUTF8=1 MLFLOW_ALLOW_FILE_STORE=true python -m qlib.cli.run path_exps/31_linear.yaml > path_exps/logs/smoke_31_linear.log 2>&1
```

看到最后打印 `IC`、`excess return with cost` 两组数字就说明通了。然后验证对比脚本：

```bash
PYTHONUTF8=1 python path_exps/compare.py
```

**应该看到一行 `31_linear` 的结果**（IC 约 0.039，计成本超额年化约 9.7%）。

> 这一步同时验证了两件事：YAML 能被正确解析（`PYTHONUTF8=1` 是必须的，见文末「三个坑」），以及 mlflow 文件后端可用。

## 二、实验总览：9 个训练类 + 10 个回测类

### 训练类实验（改标签 / 特征 / 模型）

| 编号 | 配置 | 路径 | 唯一改动 | 本机耗时 |
|---|---|---|---|---|
| 00 | `00_baseline.yaml` | 基线 | 无（加 `seed: 42` 保证可复现） | ~3 分钟 |
| 11 | `11_label_5d.yaml` | ① 标签 | 标签 → `Ref($close,-6)/Ref($close,-1)-1` | ~4 分钟 |
| 12 | `12_label_20d.yaml` | ① 标签 | 标签 → `Ref($close,-21)/Ref($close,-1)-1` | ~4 分钟 |
| 13 | `13_label_binary.yaml` | ① 标签 | 标签 → `Gt(2日收益, 0.02)` + `loss: binary` | ~4 分钟 |
| 21 | `21_csi500.yaml` | ② 因子 | 股票池 `csi300` → `csi500`（基准同步换 `SH000905`） | ~4 分钟 |
| 22 | `22_alpha360.yaml` | ② 因子 | 特征集 `Alpha158` → `Alpha360` | ~5 分钟 |
| 23 | `23_custom_factors.yaml` | ② 因子 | 在 Alpha158 上加 5 个自写价量因子 | ~5 分钟 |
| 31 | `31_linear.yaml` | ③ 模型 | `LGBModel` → `LinearModel`（ols，官方线性基准的数据加工配置） | ~1 分钟 |
| 32 | `32_doubleensemble.yaml` | ③ 模型 | `LGBModel` → `DEnsembleModel`（3 个子模型 + SR/FS） | ~11 分钟 |

### 回测类实验（只看组合与执行，复用基线预测）

路径 ④⑤ 用 `path_exps/sweep.py` 跑，**前提是 00 基线已跑完**（见第三节第 1 步）。

| 编号 | 变体 | 路径 | 改了什么 | 想回答的问题 |
|---|---|---|---|---|
| 4-1 | `topk50_ndrop5` | ④ | 基线策略（对照组） | — |
| 4-2 | `topk50_ndrop5_hold2` | ④ | `hold_thresh: 2` | 最短持有 2 天，换手降多少？ |
| 4-3 | `topk50_ndrop5_hold5` | ④ | `hold_thresh: 5` | 压得更久，收益保得住吗？ |
| 4-4 | `topk30_ndrop5` | ④ | `topk: 30` | 集中持仓，超额弹性变大吗？ |
| 4-5 | `topk100_ndrop10` | ④ | `topk: 100, n_drop: 10` | 更分散，是否接近指数？ |
| 5-1 | `base_cost` | ⑤ | 基线成本（对照组） | — |
| 5-2 | `zero_cost` | ⑤ | 成本归零 | 成本到底吃掉了多少？ |
| 5-3 | `double_cost` | ⑤ | 成本翻倍 | 策略对成本的敏感度 |
| 5-4 | `deal_vwap` | ⑤ | 成交价 `close` → `vwap` | 换成交参考价，结果变多少？ |
| 5-5 | `vol_limit_1pct` | ⑤ | 单笔不超过当日成交量 1% | 资金变大时会被截断多少（看 `ffr`）？ |
| 5-6 | `vol_limit_5pct` | ⑤ | 单笔不超过当日成交量 5% | 同上，更宽松的容量约束 |

> 已排除：`n_drop: 5 → 2`。08 篇实测过：换手和成本降一半以上，但计成本超额年化从 8.07% 掉到 2.60%。不要在 4 号扫描里重复它。

## 三、按顺序手动运行

### 第 1 步：基线（必须最先跑）

```bash
cd examples
PYTHONUTF8=1 MLFLOW_ALLOW_FILE_STORE=true OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 python -m qlib.cli.run path_exps/00_baseline.yaml > path_exps/logs/00_baseline.log 2>&1
```

**为什么必须最先跑**：路径 ④⑤的回测扫描要读这次运行留下的 `pred.pkl`。没有它，`sweep.py` 会直接退出并提示。

跑完后看日志末尾，应出现与 07/08 篇一致的基线量级（IC ≈ 0.0468，计成本超额年化 ≈ 8.07%）。

### 第 2 步：路径 ①②③（训练类，共约 35 分钟）

一次性串行跑完（脚本会把每个配置的日志写到 `path_exps/logs/`）：

```bash
PYTHONUTF8=1 python path_exps/run_all.py --only 11 12 13 21 22 23 31 32
```

也可以一次只跑一条路径，观察得更从容：

```bash
PYTHONUTF8=1 python path_exps/run_all.py --only 11 12 13   # 路径 ① 标签
PYTHONUTF8=1 python path_exps/run_all.py --only 21 22 23   # 路径 ② 因子
PYTHONUTF8=1 python path_exps/run_all.py --only 31 32      # 路径 ③ 模型
```

单独跑一个也行（和冒烟测试同样的命令，换个文件名）：

```bash
PYTHONUTF8=1 MLFLOW_ALLOW_FILE_STORE=true OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 python -m qlib.cli.run path_exps/11_label_5d.yaml > path_exps/logs/11_label_5d.log 2>&1
```

**想评估随机性**（推荐对 ① 的两个标签实验做）：

```bash
PYTHONUTF8=1 python path_exps/run_all.py --only 00 11 --repeat 3
```

`--repeat 3` 会用 seed 42/43/44 各跑一次（配置里的 `seed: 42` 会被临时替换，跑完删掉临时文件）。之后用 `python path_exps/compare.py --repeat-sd` 看均值 ± 标准差。**两次结果差 0.003 以内的，不要下结论。**

> **单次运行不可信的实验**：`32_doubleensemble` 的样本重加权和特征选择用了 `np.random` 且未固定种子，单次结果只能当参考；`13_label_binary` 也只有一次。想下结论就加 `--repeat`。

### 第 3 步：路径 ④⑤（回测类，约 10–20 分钟）

```bash
PYTHONUTF8=1 python path_exps/sweep.py --which 4       # 组合策略
PYTHONUTF8=1 python path_exps/sweep.py --which 5       # 交易执行
PYTHONUTF8=1 python path_exps/sweep.py --which all     # 一起跑
```

每个变体都会打印一行 `turnover=... excess_ann=...`，结束后写入：

- `path_exps/results/sweep_4.csv`
- `path_exps/results/sweep_5.csv`

### 第 4 步：汇总对比

```bash
PYTHONUTF8=1 python path_exps/compare.py --csv path_exps/results/path_summary.csv
```

输出一张按路径分组的总表，列包括 IC / ICIR / Rank IC / 不计成本超额年化 / 计成本超额年化 / 计成本 IR / 最大回撤 / 换手 / 成本，以及相对 00 基线的差值列（`d_IC`、`d_excess_ann`、`d_excess_ir`、`d_turnover`）。

**推荐实验顺序**：先跑基线 → 再跑 ①②③ 里你最想验证的一条 → 最后跑 ④⑤。一次只改一个变量，否则无法归因。

## 四、每个实验在验证什么

### 路径 ①：标签决定上限（投入最小，影响最大）

| 配置 | 预期 | 本机已知结论 |
|---|---|---|
| `11_label_5d` | IC 升、换手降 | 08 篇实测 IC 0.0468 → **0.0690**，计成本超额 8.07% → **10.74%** |
| `12_label_20d` | IC 更高、信号更慢 | 未验证；注意 20 日标签重叠更严重，有效样本更少 |
| `13_label_binary` | 输出「未来两天涨超 2% 的概率」 | 未验证；评估要看 IC 是否仍有效（0/1 标签下 Pearson IC 仍可用） |

**看什么**：IC 变化、换手变化、IC 的年度稳定性（是不是只靠某一年）。

### 路径 ②：因子是 qlib 的主战场

| 配置 | 预期 | 依据 |
|---|---|---|
| `21_csi500` | IC 降、年化可能升 | 官方基准：IC 0.0448 → 0.0399，年化 9.01% → 12.84% |
| `22_alpha360` | 树模型变差 | 官方基准：LightGBM Alpha158 0.0448 → Alpha360 0.0400（−11%） |
| `23_custom_factors` | 小幅提升或不显著 | 新增 5 个价量因子（20 日价量相关、10 日变异系数、20 日价格分位、收盘-均价相关、成交量趋势） |

**看什么**：`22` 用来验证「Alpha158 已经足够工程化」这个结论；`23` 用来体验「加因子」的分工——因子是手写的，模型只负责组合。

**23 的实现**：[path_exps/custom_handler.py](../examples/path_exps/custom_handler.py) 继承 `Alpha158`，在 `get_feature_config` 里追加表达式。YAML 里用 `module_path: path_exps/custom_handler.py` + `trusted: true` 引入（新版 qlib 要求显式信任 .py 模块）。

### 路径 ③：模型影响中等，耗时最长

| 配置 | 预期 | 本机已知结论 |
|---|---|---|
| `31_linear` | 明显弱于树模型 | 官方 Alpha158 IC 0.0397；本次冒烟实测 0.0392 |
| `32_doubleensemble` | IC、IR 同时提升 | 08 篇实测 IC 0.0515、计成本超额 11.14%、IR 1.31，但训练慢约 3.7 倍 |

**看什么**：把 31/32 与 00 放一起，就能看到「最复杂的模型 vs 最简单的模型 vs 默认模型」三者的差距。线性模型只有 158 个参数，如果它和 LightGBM 差距很小，说明数据里几乎没有可学的交互。

### 路径 ④：同样的信号，组合方式不同

**看什么**：换手（`turnover`）、计成本超额年化（`excess_ann`）、IR 三列一起看。

- `hold2` / `hold5`：换手下来了，收益保住了吗？如果收益跟着掉，说明和 `n_drop` 一样是「硬约束砍掉信号」
- `topk30` / `topk100`：IC 完全不变（同一个预测），变化的只有收益曲线形态

### 路径 ⑤：执行成本的影响有多大

**看什么**：

- `zero_cost` 与 `base_cost` 的差 = 成本的总代价（对应 07 篇「8.07% vs 12.60%」）
- `double_cost` 用来估算「实盘成本比回测高」时的安全边际
- `vol_limit_*` 要看 **`ffr`（成交率）**：`ffr` 掉到 0.8 以下，说明按 1 亿元资金、1%/5% 的成交量上限会被截断，实盘容量不足（当前基线 `ffr = 1.0`，即完全不构成约束）

## 五、怎么判断「真的有效」

三条都要看，缺一条就可能自欺（详见 08 篇「判断改进是否真的有效」）：

1. **IC 提升超过噪声**：单次 IC 的随机波动约 ±0.003。想确认有效，用 `--repeat 3` 重跑看均值
2. **分年稳定**：新方案不能只靠某一年（读 `sig_analysis/ic.pkl` 按年分组）
3. **成本没吃掉收益**：IC 涨了但计成本年化没涨，多半是换手上升

另外两个容易忽略的：

- **`ffr` 与 `turnover`**：路径 ④⑤ 的所有变体都要看这两列
- **训练耗时**：32 号实验训练时间约为基线的 3.7 倍，收益提升要配得上这个成本

## 六、三个坑（已在本方案里规避）

1. **`Greater()` 不是「大于」判断**
   qlib 的 `Greater` 实际是逐元素取较大值（`maximum`），返回的是收益率本身而不是 0/1。要做分类标签，必须用 `Gt()`：
   ```
   label: ["Gt(Ref($close, -2)/Ref($close, -1) - 1, 0.02)"]   # 正确
   label: ["Greater(Ref($close, -2)/Ref($close, -1) - 1, 0.02)"]  # 错误：返回 0.02 或收益率
   ```

2. **qlib 在中文 Windows 上用 GBK 读 YAML**
   `qlib/cli/run.py` 用 `open(config_path)`（默认编码）读配置。本机 locale 是 cp936，UTF-8 中文会直接报 `UnicodeDecodeError`。**所有命令都带 `PYTHONUTF8=1`**。
   - `00_baseline.yaml` 带中文注释（UTF-8），必须靠 `PYTHONUTF8=1`；`run_all.py` 已在子进程环境里设置好，通过它跑不受影响
   - 其余 8 个变体配置保持纯 ASCII，直接 `qrun` 也能读

3. **`volume_threshold` 无法用 YAML 表达**
   它是 `("current", "0.01 * $volume")` 这样的 tuple，ruamel 的 safe loader 不支持 `!!python/tuple`。所以容量实验只能走 Python（`sweep.py`），不要试图写进 YAML。

### 附加说明

- **对比脚本需要 `MLFLOW_ALLOW_FILE_STORE=true`**：`compare.py` 已在文件里 `setdefault`，手动运行时不必再加
- **`13_label_binary` 覆盖了默认的 label 加工器**：默认的 `CSZScoreNorm(label)` 会对 0/1 标签做截面 z-score，把类别信息破坏掉。所以该配置把 `learn_processors` 改成只有 `DropnaLabel`
- **`21_csi500` 的价格数据从 2007 年才有**（csi500 成分历史起点），2008 训练起点不受影响
