# 04 工作流篇：qrun 配置与实验管理

`qrun` 用一个 YAML 定义整条研究流水线，一条命令跑完。本文讲清配置怎么组织、内部怎么执行、结果怎么管理。

---

## 一、qrun 做什么

Qlib 的各组件（Data、Model、Evaluation）是**松耦合**的，你可以自己用 Python 拼装（见 [examples/workflow_by_code.py](../examples/workflow_by_code.py)）。

`qrun` 是把这套拼装过程**声明式化**的接口。一次完整执行包含：

```
① Data      加载 → 加工 → 切分
② Model     训练 → 推理 → 保存/加载
③ Evaluation 信号分析（IC）→ 回测
```

每次执行都被 `Recorder` 完整记录：配置、模型、预测、指标、产物。

---

## 二、配置文件的组织逻辑

设计逻辑极简：**每个组件用 `class` + `module_path` + `kwargs` 三件套描述**，由 `init_instance_by_config` 统一实例化（[qlib/utils/__init__.py:264](../qlib/utils/__init__.py)）。

YAML 和 Python 是等价的：

```yaml
model:
    class: LGBModel
    module_path: qlib.contrib.model.gbdt
    kwargs:
        loss: mse
        learning_rate: 0.0421
        max_depth: 8
        num_leaves: 210
```

```python
from qlib.contrib.model.gbdt import LGBModel
LGBModel(loss="mse", learning_rate=0.0421, max_depth=8, num_leaves=210)
```

**记住这个三件套，就能配置 Qlib 里的任何组件**——模型、数据集、策略、记录器都一样。

## 三、顶层结构

```yaml
qlib_init:          # ① 全局初始化
    provider_uri: "~/.qlib/qlib_data/cn_data"
    region: cn
    kernels: 1

market: &market csi300            # 锚点：股票池
benchmark: &benchmark SH000300    # 锚点：基准

data_handler_config: &data_handler_config    # 锚点：数据配置
    start_time: 2008-01-01
    end_time: 2020-08-01
    fit_start_time: 2008-01-01
    fit_end_time: 2014-12-31
    instruments: *market

port_analysis_config: &port_analysis_config  # 锚点：回测配置
    strategy: {...}
    backtest: {...}

task:               # ② 一个任务
    model: {...}
    dataset: {...}
    record: [...]
```

### qlib_init 段

| 字段 | 类型 | 含义 |
|---|---|---|
| `provider_uri` | str / dict | 数据路径。`get_data.py` 下载的数据放这里 |
| `region` | str | `cn` = A股模式，`us` = 美股模式 |
| `kernels` | int | 并行进程数。默认 `CPU核数-2`，建议设 `1` |
| `expression_cache` | str | 表达式缓存（可选，`null` 关闭） |
| `dataset_cache` | str | 数据集缓存（可选） |

> ⚠️ `region` 必须和 `provider_uri` 里的数据匹配。A 股数据配 `us` 会导致交易规则错误（涨跌停、整手）。

### task 段

一个 `task` = 一次「训练 + 评估」的完整描述，包含三部分：

```
task
├── model      用什么模型、什么超参
├── dataset    什么数据、怎么切分
└── record     训练完做什么（存预测、算IC、回测）
```

## 四、model 段

```yaml
model:
    class: LGBModel
    module_path: qlib.contrib.model.gbdt
    kwargs:
        loss: mse
        colsample_bytree: 0.8879
        learning_rate: 0.2
        subsample: 0.8789
        lambda_l1: 205.6999
        lambda_l2: 580.9768
        max_depth: 8
        num_leaves: 210
        num_threads: 2
```

| 字段 | 含义 |
|---|---|
| `class` | 模型类名 |
| `module_path` | 类所在的模块路径 |
| `kwargs` | 传给该类 `__init__` 的参数 |

**超参含义**（LightGBM）：

| 参数 | 本次值 | 作用 |
|---|---|---|
| `loss` | mse | 回归任务（预测收益率） |
| `learning_rate` | 0.2 | 学得快，易过拟合（官方调优值） |
| `max_depth` | 8 | 树深 |
| `num_leaves` | 210 | 叶子数 |
| `lambda_l1` / `lambda_l2` | 205 / 581 | **强正则化**——金融数据信噪比极低，必须重压 |
| `num_boost_round` | 1000（默认） | 最多 1000 棵树 |
| `early_stopping_rounds` | 50（默认） | valid 上 50 轮不提升就停 |

**全部模型列表**见 [模型篇](05-模型篇.md)。

## 五、dataset 段

```yaml
dataset:
    class: DatasetH
    module_path: qlib.data.dataset
    kwargs:
        handler:
            class: Alpha158            # 用哪个数据处理器
            module_path: qlib.contrib.data.handler
            kwargs: *data_handler_config
        segments:                      # 时间切分
            train: [2008-01-01, 2014-12-31]
            valid: [2015-01-01, 2016-12-31]
            test:  [2017-01-01, 2020-08-01]
```

### handler 的配置

```yaml
data_handler_config:
    start_time: 2008-01-01      # 数据起始
    end_time: 2020-08-01        # 数据结束
    fit_start_time: 2008-01-01  # Processor 学习参数的区间
    fit_end_time: 2014-12-31
    instruments: csi300         # 股票池
```

**关键**：`fit_start_time`/`fit_end_time` 决定标准化的 mean/std 从哪段数据学。

> ⚠️ 如果把 `fit_end_time` 设到测试期末，**标准化就用了未来信息**——这是最隐蔽的前视偏差，IC 会虚高但实盘崩盘。

### segments 的划分原则

| 段 | 用途 | 要求 |
|---|---|---|
| `train` | 训练模型 | 时间最早 |
| `valid` | 早停、调参 | 在 train 之后 |
| `test` | 评估 | 在 valid 之后 |

**必须严格按时间先后**，绝不能随机切分（那是前视偏差）。

## 六、record 段

`Record` 负责把训练结果**标准化地记录**下来。

```yaml
record:
    - class: SignalRecord
      module_path: qlib.workflow.record_temp
      kwargs:
        model: <MODEL>
        dataset: <DATASET>
    - class: SigAnaRecord
      module_path: qlib.workflow.record_temp
      kwargs:
        ana_long_short: False
        ann_scaler: 252
    - class: PortAnaRecord
      module_path: qlib.workflow.record_temp
      kwargs:
        config: *port_analysis_config
```

### 占位符

`<MODEL>`、`<DATASET>`、`<PRED>` 是占位符，由 `fill_placeholder` 在运行时替换（[qlib/utils/__init__.py:857](../qlib/utils/__init__.py)）：

```python
placehorder_value = {"<MODEL>": model, "<DATASET>": dataset}
```

| 占位符 | 替换成 |
|---|---|
| `<MODEL>` | 训练好的模型实例 |
| `<DATASET>` | 数据集实例 |
| `<PRED>` | 预测结果（`pred.pkl`） |

> 运行日志里的 `<PRED> lookes like a placeholder, but it can't match...` 是正常提示——`<PRED>` 要等到 `PortAnaRecord` 执行时才可用。

### 三个 Record 的职责

| Record | 做什么 | 产出 |
|---|---|---|
| `SignalRecord` | 存预测和原始标签 | `pred.pkl`、`label.pkl` |
| `SigAnaRecord` | 算 IC / Rank IC | `ic.pkl`、`ric.pkl` + metrics |
| `PortAnaRecord` | 回测 | `report_normal_1day.pkl`、`positions_*.pkl`、`indicator_*.pkl` |

**必须按顺序**：`SigAnaRecord` 依赖 `pred.pkl`，`PortAnaRecord` 依赖 `<PRED>`。

指标含义见 [指标篇](07-指标篇.md)。

### 回测配置

```yaml
port_analysis_config:
    strategy:
        class: TopkDropoutStrategy
        module_path: qlib.contrib.strategy
        kwargs:
            signal: <PRED>
            topk: 50        # 持有 50 只
            n_drop: 5       # 每天最多换 5 只
    backtest:
        start_time: 2017-01-01
        end_time: 2020-08-01
        account: 100000000      # 初始资金 1 亿
        benchmark: SH000300     # 基准沪深300
        exchange_kwargs:
            limit_threshold: 0.095   # 涨跌停阈值
            deal_price: close        # 按收盘价成交
            open_cost: 0.0005        # 买入费率 5bp
            close_cost: 0.0015       # 卖出费率 15bp
            min_cost: 5              # 每笔最低 5 元
```

策略细节见 [回测篇](06-回测篇.md)。

## 七、执行流程

`qrun` 调用 [qlib/model/trainer.py:44](../qlib/model/trainer.py) 的 `_exe_task`：

```python
def _exe_task(task_config):
    # ① 初始化
    qlib.init(**task_config["qlib_init"])

    # ② 建数据集
    dataset = init_instance_by_config(task_config["dataset"])

    # ③ 训练模型
    model = init_instance_by_config(task_config["model"])
    model.fit(dataset)

    # ④ 替换占位符
    task_config = fill_placeholder(task_config, {"<MODEL>": model, "<DATASET>": dataset})

    # ⑤ 按顺序执行 Record
    for record in task_config["record"]:
        record = init_instance_by_config(record)
        record.generate()
```

每一步耗时（本次实测）：

| 阶段 | 耗时 |
|---|---|
| 初始化 | < 1 秒 |
| 建 Dataset | **71 秒**（最久） |
| 训练 | 15 秒（早停在第 18 轮） |
| SignalRecord | 1 秒 |
| SigAnaRecord | 1 秒 |
| PortAnaRecord（回测） | 12 秒 |

## 八、Recorder：实验管理

每次运行都会创建一个 `Experiment` 和一个 `Recorder`。

### 目录结构

```
examples/mlruns/
└── 740576277429403079/              ← Experiment ID
    └── 3a76e5cd5b8245cba963fea3ca876d1d/   ← Recorder ID
        ├── artifacts/
        │   ├── config               ← 完整配置快照
        │   ├── params.pkl           ← 训练好的模型
        │   ├── pred.pkl             ← 预测
        │   ├── label.pkl            ← 真实标签
        │   ├── sig_analysis/
        │   │   ├── ic.pkl
        │   │   └── ric.pkl
        │   └── portfolio_analysis/
        │       ├── report_normal_1day.pkl
        │       ├── positions_normal_1day.pkl
        │       └── indicator_analysis_1day.pkl
        ├── metrics/                 ← 标量指标
        ├── params/                  ← 超参
        └── tags/
```

### 用代码访问

```python
from qlib.workflow import R

# 列出所有实验
exps = R.list_experiments()
print(exps)

# 获取某个实验
exp = R.get_exp(experiment_name="740576277429403079")
recorders = exp.list_recorders()

# 取最新一次
recorder = list(recorders.values())[0]
print(recorder.list_metrics())      # 所有指标
pred = recorder.load_object("pred.pkl")
```

### 对比实验

```python
import pandas as pd

# 收集多次实验的 IC
results = {}
for exp_id in ["740576277429403079", "..." ]:
    exp = R.get_exp(experiment_name=exp_id)
    rec = list(exp.list_recorders().values())[0]
    metrics = rec.list_metrics()
    results[exp_id] = metrics["IC"]
```

**建议**：每次实验用不同的 `experiment_name`（可以在 `qlib.init` 里设 `exp_manager`），便于区分。

## 九、用代码代替 YAML

不想用 YAML？可以完全用 Python 写（见 [examples/workflow_by_code.py](../examples/workflow_by_code.py)）：

```python
import qlib
from qlib.data.dataset import DatasetH
from qlib.contrib.data.handler import Alpha158
from qlib.contrib.model.gbdt import LGBModel
from qlib.workflow import R
from qlib.workflow.record_temp import SignalRecord, SigAnaRecord, PortAnaRecord

qlib.init(provider_uri="~/.qlib/qlib_data/cn_data", region="cn", kernels=1)

handler = Alpha158(instruments="csi300",
                   start_time="2008-01-01", end_time="2020-08-01",
                   fit_start_time="2008-01-01", fit_end_time="2014-12-31")
dataset = DatasetH(handler=handler, segments={
    "train": ("2008-01-01", "2014-12-31"),
    "valid": ("2015-01-01", "2016-12-31"),
    "test":  ("2017-01-01", "2020-08-01"),
})

model = LGBModel(loss="mse", max_depth=8, num_leaves=210, num_threads=2)
model.fit(dataset)

with R.start(experiment_name="my_exp"):
    recorder = R.get_recorder()
    SignalRecord(model, dataset, recorder).generate()
    SigAnaRecord(recorder).generate()
    PortAnaRecord(recorder, config=port_config).generate()
```

**YAML 和代码完全等价**，前者适合快速实验，后者适合嵌进自己的系统。

## 十、常见配置错误

| 现象 | 原因 | 解决 |
|---|---|---|
| `ValueError: n_jobs == 0` | `kernels: 0` | 改 `kernels: 1` |
| `assert fit_start_time is not None` | 用了 `ZScoreNorm` 但没给 fit 区间 | 补 `fit_start_time`/`fit_end_time` |
| `<PRED> can't match` | 占位符在 `PortAnaRecord` 之前出现 | 正常，忽略 |
| `Empty data from dataset` | 时间段内没有数据 | 检查日期区间和股票池 |
| IC 异常高（>0.1） | `fit_end_time` 越界到测试期 | 改成训练期末 |
| 内存溢出 | 时间区间太长、股票池太大 | 缩小范围 |
