# 模型详解：26 个模型有什么区别，该怎么选

qlib 内置 26 个模型（见 [examples/benchmarks/](../examples/benchmarks/)）。本文按**数学结构**把它们分成 5 类，给出官方基准成绩，并说明选型的判断逻辑。

> 数据来源：[examples/benchmarks/README.md](../examples/benchmarks/README.md)，CSI300 + Alpha158/Alpha360，每项为 **20 次不同随机种子运行的均值±标准差**。
> 指标定义见 [指标篇](07-指标篇.md)。

---

## 一、五大类模型

### ① 线性模型

**实现**：[qlib/contrib/model/linear.py](../qlib/contrib/model/linear.py)

```python
# ols:   min_w |y - Xw|^2_2
# nnls:  min_w |y - Xw|^2_2,  s.t. w >= 0
# ridge: min_w |y - Xw|^2_2 + α|w|^2_2
# lasso: min_w |y - Xw|^2_2 + α|w|_1
```

**本质**：给 158 个因子各学一个权重，`预测 = w₁x₁ + w₂x₂ + ... + w₁₅₈x₁₅₈`。

**特点**：
- 只有 158 个参数，训练 1 秒内完成
- **无法表达因子之间的交互**（「低波动且高动量」这种组合它学不到）
- 系数 `w` 就是因子权重，**可解释性最好**

**定位**：基线中的基线。任何复杂模型如果打不过线性模型，说明模型没学到东西。

**Alpha158 IC = 0.0397**，其实不算差。

---

### ② 树模型（LightGBM / XGBoost / CatBoost）

**实现**：[gbdt.py](../qlib/contrib/model/gbdt.py)、[xgboost.py](../qlib/contrib/model/xgboost.py)、[catboost_model.py](../qlib/contrib/model/catboost_model.py)

**本质**：一系列决策树，每棵树修正前面所有树的残差。预测值 = 所有树叶节点值之和。

**三者差异**：

| 模型 | 建树方式 | 特点 |
|---|---|---|
| **LightGBM** | 叶子优先生长（leaf-wise）+ 直方图分箱 | 最快，内存最省，qlib 默认 |
| **XGBoost** | 层序生长（level-wise）+ 预排序 | 精度通常略高，慢一些 |
| **CatBoost** | 对称树 + 有序目标编码 | 对类别特征友好，不易过拟合 |

**为什么树模型在 Alpha158 上这么强**（IC 0.045~0.050）：

1. Alpha158 是**表格数据**，158 个因子是并列关系，没有时间顺序
2. 树模型天然擅长**特征交互**和**非线性**
3. 对特征尺度不敏感，不需要额外归一化
4. 金融数据信噪比极低，树的正则化（`lambda_l1=205`、`lambda_l2=581`）能有效压制噪声

**这就是官方默认示例用 LightGBM 的原因——性价比最高。**

`LGBModel.fit` 的核心只有几行（[gbdt.py:25](../qlib/contrib/model/gbdt.py)）：

```python
df = dataset.prepare("train", col_set=["feature", "label"], data_key=DataHandlerLP.DK_L)
lgb.train(params, lgb.Dataset(x.values, label=y), num_boost_round=1000, valid_sets=..., callbacks=[early_stopping(50)])
```

### ③ 循环神经网络（LSTM / GRU / ALSTM / KRNN / ADARNN）

**实现**：[pytorch_lstm.py](../qlib/contrib/model/pytorch_lstm.py)、[pytorch_gru.py](../qlib/contrib/model/pytorch_gru.py)、[pytorch_alstm.py](../qlib/contrib/model/pytorch_alstm.py) 等

**本质**：把股票过去 60 天（`step_len`）的数据当成一个**序列**，用 RNN 逐日读取并维护隐藏状态。

```
输入形状: (batch, timestep, feature) = (2000, 60, 158 或 20)
```

**关键区别**：

| 模型 | 核心机制 |
|---|---|
| **LSTM / GRU** | 标准序列建模，门控机制记住长期依赖 |
| **ALSTM** | LSTM + 注意力，让模型自己决定「过去哪几天最重要」 |
| **ADARNN** | 处理**分布漂移**，训练期与测试期市场特征不同时更鲁棒 |
| **KRNN** | 用可学习的时间核代替固定注意力 |

**前提**：必须用 `TSDatasetH`，对应 `*_ts.py` 文件。README 的 FAQ 明确说明：

> `*_ts.py` 是为 `TSDatasetH` 设计的，`*.py` 是为 `DatasetH`（表格）设计的。

`TSDatasetH` 会自动把表格数据切成时间窗口（[qlib/data/dataset/__init__.py:642](../qlib/data/dataset/__init__.py)）：

```python
class TSDatasetH(DatasetH):
    DEFAULT_STEP_LEN = 30
    def _extend_slice(self, slc, cal, step_len):
        # 往前多取 step_len 天，保证每个样本都有完整的时间窗口
        pad_start_idx = max(0, start_idx - step_len)
        return slice(cal[pad_start_idx], slc.stop)
```

### ④ Transformer 系（Transformer / Localformer / TRA / TFT）

**本质**：用**自注意力**替代 RNN 的循环。每一天的数据可以「直接看到」任意其他天，不用一步步传递。

| 模型 | 核心思想 |
|---|---|
| **Transformer** | 标准自注意力，全序列两两相关 |
| **Localformer** | 局部注意力 + Transformer，更关注近期邻域 |
| **TRA** | 时序 + 跨股票两个维度都做注意力（Temporal Routing Adaptor） |
| **TFT** | 可解释的时序融合，输出带注意力权重 |

**一个反直觉但重要的结果**：标准 Transformer 在 Alpha158 上 IC 只有 **0.0264**，还不如线性模型的 0.0397。

**原因**：
- Alpha158 的 158 个因子**已经被人工设计成「提好特征」的表格**，没有时间序列结构
- Transformer 的强项（长程依赖）在这里没发挥余地
- 参数多 → 在低信噪比的金融数据上**过拟合**

**一旦换成 Alpha360**（原始 60 天价量，有强时序结构），Transformer 系的表现就上来了。

**这是「模型要看数据形态」的最好例子。**

---

### ⑤ 图神经网络 / 集成模型

#### 图神经网络（GATs / HIST / IGMTF）

**核心思想**：把**股票之间的关系**建成图（同行业、上下游、概念板块），用图注意力传播信息。

- **GATs**：图注意力网络，学习股票间的动态关联
- **HIST**：HISTorical 信息 + 概念图，Alpha360 上 IC **0.0522**，是所有模型里最高的
- **IGMTF**：可学习的关系矩阵，不依赖预定义行业分类

#### 集成模型（DoubleEnsemble）

**实现**：[double_ensemble.py](../qlib/contrib/model/double_ensemble.py)

**三重机制**：
1. **样本重加权**：给难样本更高权重（类似 AdaBoost 思想）
2. **特征选择**：每轮随机选特征子集，降低相关性
3. **多模型集成**：多个基模型平均

**基模型是 LGBM**（README 明确说明）。

**Alpha158 上 IC 0.0521、年化 11.58%、IR 1.3432**，是 CSI300 上综合最好的。

## 三、三个反直觉但重要的发现

### ① 复杂模型不一定赢

标准 Transformer（IC 0.0264）不如线性模型（0.0397）。在 Alpha158 这种「已经提好特征」的表格数据上，参数越多越容易过拟合。

### ② IC 高不等于赚得多

MLP 的 IC 只有 0.0376，但年化 8.95% 高于 CatBoost 的 7.65%（IC 0.0481）。

原因：**IC 衡量的是排序能力，组合收益还取决于 IC 的分布形状、换手率和成本**。MLP 的 IC 分布可能更稳定，做组合时损耗更小。

### ③ 换数据集会重新洗牌

同一个 ALSTM：
- Alpha158 上 IC 0.0362
- Alpha360 上 IC 0.0497

LightGBM 则相反：
- Alpha158 上 IC 0.0448
- Alpha360 上 IC 0.0400

**这说明「模型表现」是模型和数据形态的联合结果，不能单独评价模型。**

README 也说得很清楚：

> We have very limited resources to implement and finetune the models... some models may have greater potential than what it looks like in the table below.

**表里的排名反映的是「官方配置调得好不好」，不是「模型本身的上限」。**

## 四、选型决策

| 你的情况 | 选什么 | 理由 |
|---|---|---|
| **第一次跑 / 想要基线** | LightGBM + Alpha158 | 官方默认，快，结果稳定 |
| **想榨干表格数据的性能** | DoubleEnsemble、XGBoost | DoubleEnsemble IC 最高 |
| **想处理原始价量序列** | Alpha360 + HIST / LSTM / GRU | HIST 在 Alpha360 上 IC 最高 |
| **想利用股票间关系** | GATs / HIST / IGMTF | 需要行业分类或概念板块数据 |
| **要可解释性** | Linear、LightGBM | 系数 / 特征重要性直接可读 |
| **数据量小、怕过拟合** | Linear / Ridge | 参数少 |
| **算力有限（CPU only）** | 树模型 / 线性 | PyTorch 系需要 GPU 才现实 |
| **要处理分布漂移** | AdaRNN | 专为非平稳分布设计 |

### 两条实操原则

1. **永远先跑 Linear 和 LightGBM 作对照。** 复杂模型打不过这两个，问题在数据或配置，不在模型。
2. **换数据集的收益通常大于换模型。** Alpha158 → Alpha360 带来的变化，往往比换模型更大。

## 五、训练数据准确度最终取决于什么

**IC 的天花板不在模型，在数据。** 按影响力从大到小：

| 层级 | 因素 | 影响 | 能否改变 |
|---|---|---|---|
| 1 | **标签定义** | 决定上限 | 物理约束，改不了 |
| 2 | **特征质量** | 最大可调因素 | 换数据集 |
| 3 | **数据干净度** | 前视偏差可毁掉一切 | 检查 + 换数据源 |
| 4 | **数据加工** | 标准化/缺失处理 | 调 processor |
| 5 | **模型与超参** | 约 ±15% | 最后再调 |

### 第 1 层：标签

qlib 默认：

```
Ref($close, -2) / Ref($close, -1) - 1
```

即 **T+1 收盘买入、T+2 收盘卖出**的收益。这一行决定了整个系统的天花板。

| 标签选择 | 后果 |
|---|---|
| `Ref($close,-1)/$close - 1` | **有前视偏差**，回测虚高 |
| `Ref($close,-2)/Ref($close,-1)-1` | 正确，符合 A 股 T+1 |
| 预测 5 日 / 20 日收益 | IC 通常更高，换手更低 |
| 减去行业收益做中性化 | IC 降但超额更稳 |

A 股日频的 IC 上限大概在 0.05~0.08，**再高基本都是有 bug**。

### 第 2 层：特征质量（也叫「因子」）

**先厘清一个最容易混的点**：

| 概念 | 是什么 | 举例 |
|---|---|---|
| **原始数据**（第 3 层） | 交易所给的最基本数据 | 每天的开盘价、最高价、最低价、收盘价、成交量 |
| **特征 / 因子**（第 2 层） | 从原始数据**算出来的、有预测含义的指标** | 「过去5天涨幅」「20天波动率」「上影线占比」 |
| **数据加工**（第 4 层） | 把算好的特征**换成另一种数值形式** | 标准化、填缺失值 |

**关键区别**：
- 第 2 层回答「**算什么**」——你决定用哪些指标去预测
- 第 4 层回答「**算完之后怎么摆**」——数值怎么缩放、怎么补洞

原始数据永远是 OHLCV 那 5 个数，**特征是从这 5 个数里「榨」出来的信息**。

#### 实际的因子长什么样

我从源码里打出了真实定义（[qlib/contrib/data/loader.py](../qlib/contrib/data/loader.py)）：

**Alpha158 的前 14 个因子**：

```
($close-$open)/$open                          ← K线实体占开盘价比例
($high-$low)/$open                            ← 振幅
($close-$open)/($high-$low+1e-12)             ← 实体占振幅比例
($high-Greater($open,$close))/$open           ← 上影线
(Less($open,$close)-$low)/$open               ← 下影线
(2*$close-$high-$low)/$open                   ← 收盘在区间中的位置
$open/$close  $high/$close  $low/$close       ← 价格比例
$vwap/$close                                  ← 均价与收盘价之比
Ref($close,5)/$close                          ← 5 天前收盘 / 今天收盘（5日动量）
...
```

加上 `rolling` 部分的 `Mean/Std/Slope/Rsquare/Resi/Rank/Qtl/Max/Min/Corr/Cntp/Sum` × 窗口 `[5,10,20,30,60]`，共 158 个。

**Alpha360 的前 14 个因子**：

```
Ref($close,59)/$close    ← 59 天前的收盘价
Ref($close,58)/$close    ← 58 天前的收盘价
Ref($close,57)/$close
...
Ref($close,46)/$close
```

**这就是两种「特征质量」的代表**：

| 数据集 | 特征是什么 | 相当于 | 适合谁 |
|---|---|---|---|
| **Alpha158** | **人类专家设计好的指标**——动量、波动率、趋势强度、超买超卖… | 已经切好、配好料的净菜 | 树模型、线性模型 |
| **Alpha360** | **原始价格序列**——就是过去 60 天的收盘/开盘/最高/最低/成交量，按顺序摆好 | 生的食材，让模型自己学怎么切 | LSTM、Transformer 等序列模型 |

**所以「特征质量」= 你喂给模型的这些指标，本身含多少预测信息。**

- Alpha158 已经把「什么是有用的形态」编码进去了 → 简单的树模型就能直接用
- Alpha360 什么都没有编码 → 强模型（LSTM/Transformer）能自己从序列里学出模式，但弱模型（线性/MLP）学不到

这解释了为什么换数据集会让模型排名大洗牌：

| 模型 | Alpha158 | Alpha360 | 变化 |
|---|---|---|---|
| LightGBM | 0.0448 | 0.0400 | ↓ 变差 |
| ALSTM | 0.0362 | 0.0497 | ↑ **大幅变好** |

**树模型吃「已经提好的特征」，序列模型吃「原始序列」**——特征形态和模型必须匹配。

#### 怎么自己造特征

qlib 的因子就是**表达式字符串**，写进 YAML 就能用：

```yaml
handler:
    kwargs:
        label: ["Ref($close, -2)/Ref($close, -1) - 1"]
```

例如想加「收盘价 / 20日均线」这个因子：

```
$close/Mean($close,20)
```

表达式支持 `Ref / Mean / Std / Slope / Rsquare / Resi / Rank / Greater / Less / Corr / Max / Min / Sum / If` 等算子，定义见 [docs/advanced/alpha.rst](../docs/advanced/alpha.rst)。

### 第 3 层：数据干净度

**① 前视偏差** —— 量化里最致命的错误，IC 会虚高到 0.1 以上

qlib 的防护在配置里：

```yaml
fit_start_time: 2008-01-01
fit_end_time: 2014-12-31   # ZScoreNorm 的 mean/std 只在这里学
```

**② 数据源质量** —— qlib 下载时会警告：

> The data for the example is collected from Yahoo Finance... quality might not be perfect.

已知问题：复权处理不一致（`factor.day.bin` 缺失）、停牌/涨跌停价可能有误、早期年份数据更差。

**③ 股票池**

| 池子 | IC | 特点 |
|---|---|---|
| csi300 | 较高 | 大盘股，噪声低，alpha 空间小 |
| csi500 | 较低 | 中盘股，alpha 空间大 |
| all | 最低 | 含小盘/ST，潜在收益最高 |

csi500 上 LightGBM 的 IC 0.0399（低于 csi300 的 0.0448），但**年化 12.84% 反而更高**——再次说明 IC ≠ 收益。

**④ 样本期划分**

```yaml
train: [2008-01-01, 2014-12-31]
valid: [2015-01-01, 2016-12-31]
test:  [2017-01-01, 2020-08-01]
```

三个区间**必须严格按时间先后**，不能随机切分。`DatasetH` 强制按时间切片。

### 第 4 层：数据加工（processor）

**定义**：特征算出来之后、喂给模型之前，做的一层**数值变换**。它不改变「算什么因子」（那是第 2 层），只改变「因子的数值长什么样」。

**⚠️ 一个重要事实**：`Alpha158` 和 `Alpha360` 的默认 processor **不一样**（[qlib/contrib/data/handler.py](../qlib/contrib/data/handler.py)）：

```python
_DEFAULT_INFER_PROCESSORS = [                       # ← Alpha360 用
    {"class": "ProcessInf"},
    {"class": "ZScoreNorm"},
    {"class": "Fillna"},
]
_DEFAULT_LEARN_PROCESSORS = [                       # ← 两者都用
    {"class": "DropnaLabel"},
    {"class": "CSZScoreNorm", "kwargs": {"fields_group": "label"}},
]

class Alpha158(...):
    def __init__(..., infer_processors=[], ...):    # ← 默认空列表！
```

| 数据集 | infer_processors 默认值 |
|---|---|
| `Alpha360` | `ProcessInf` + `ZScoreNorm` + `Fillna` |
| `Alpha158` | **`[]`（什么都不做）** |

官方 LightGBM 配置和 `my_first_run.yaml` 都**没有显式指定** `infer_processors`，所以跑 Alpha158 时**实际只执行了 2 个 learn processor**。

#### 每个 processor 在做什么

| Processor | 作用 | 本次是否生效 |
|---|---|---|
| `ProcessInf` | 无穷值 → 该列均值 | ❌ Alpha158 默认不启用 |
| `ZScoreNorm` | 按**时间** z-score，用 fit 区间学 mean/std | ❌ Alpha158 默认不启用 |
| `Fillna` | 缺失填 0 | ❌ Alpha158 默认不启用 |
| `DropnaLabel` | 丢掉标签缺失的行 | ✅ |
| `CSZScoreNorm` | 按**截面** z-score（同一天跨股票） | ✅（只作用于 label） |

#### 实测对比：加工到底改变了什么

用 2019-01-01~2020-08-01 的 csi300 数据实测：

| 统计量 | 默认 Alpha158（无加工） | 手动加上 3 个 infer processor |
|---|---|---|
| KMID mean / std | 0.0016 / 0.0219 | 0.0188 / **1.0667** |
| MA5 mean / std | 0.9986 / 0.0276 | 0.0190 / **1.1441** |
| STD20 mean / std | 0.0392 / 0.0270 | 0.1302 / **1.1125** |
| ROC60 mean / std | 0.9834 / 0.1695 | 0.0457 / **1.0291** |
| **NaN 数量** | **197,754** | **0** |

**两件事一目了然**：

1. **`ZScoreNorm` 把所有列拉到同尺度**：加工后每列 std ≈ 1、mean ≈ 0。这就是标准化的唯一目的——让 158 个量纲不同的因子在模型眼里「一样大」。
2. **`Fillna` 把 19 万个 NaN 清零**：滚动窗口前 N 天没有足够历史，天然产生 NaN。

#### 为什么 Alpha158 不加工也能跑

因为：

- **Alpha158 的因子天生无量纲**：`($close-$open)/$open`、`Mean($close,5)/$close` 全是比值，量级都在 0.001~2 之间
- **树模型对尺度不敏感**：决策树只看「大于/小于某个阈值」，把一列乘 100 不改变分裂结果
- **LightGBM 能自己处理 NaN**：会把它分到某个分支

**所以默认配置能跑出 IC≈0.047。**

#### 但换成神经网络就必须加工

| 场景 | 是否需要 processor | 原因 |
|---|---|---|
| 树模型（LightGBM/XGBoost） | 可选 | 对尺度不敏感，能处理 NaN |
| 线性模型 | **需要** | 不同量纲的系数不可比，正则化会失衡 |
| 神经网络（LSTM/Transformer） | **必须** | 输入尺度过大会让梯度爆炸/消失；NaN 直接传播 |
| 使用 Alpha360 | 已默认启用 | 价格序列量级差异更大 |

**实操**：如果你要把模型换成 PyTorch 系，在配置里显式加上：

```yaml
handler:
    class: Alpha158
    module_path: qlib.contrib.data.handler
    kwargs:
        infer_processors:
            - class: ProcessInf
            - class: ZScoreNorm
            - class: Fillna
        learn_processors:
            - class: DropnaLabel
            - class: CSZScoreNorm
              kwargs: {fields_group: label}
        fit_start_time: 2008-01-01
        fit_end_time: 2014-12-31
```

#### 两层数据流

`DataHandlerLP` 会同时保留两套数据（[qlib/data/dataset/handler.py:570](../qlib/data/dataset/handler.py)）：

```
原始数据 ──shared_processors──┬─→ infer_processors → _infer  （推理/预测用）
                              └─→ learn_processors → _learn  （训练用）
```

源码里的注释说得很直白：

> `(self._data)-[shared_processors]-(_shared_df)-[infer_processors]-(_infer_df)-[learn_processors]-(_learn_df)`

模型的 `fit()` 读 `DK_L`（learn 流），`predict()` 读 `DK_I`（infer 流）。

#### `ZScoreNorm` 的 fit 区间为什么重要

如果启用了 `ZScoreNorm`，它的 mean/std **只从 `fit_start_time`~`fit_end_time` 这段数据学**，再套用到全部数据。

```yaml
fit_start_time: 2008-01-01
fit_end_time: 2014-12-31   # ← 只在这里学 mean/std
```

**如果把 `fit_end_time` 设到测试期末（2020-08-01），标准化就用了未来信息**——这是最隐蔽的前视偏差之一，IC 会虚高但实盘崩盘。

### 第 5 层：模型与超参

这一层影响最小：

- 线性 → LightGBM：IC 0.0397 → 0.0448（**+13%**）
- LightGBM → DoubleEnsemble：0.0448 → 0.0521（**+16%**）
- **标签定义错一天**：IC 可能虚高 100% 然后实盘全亏

官方超参已经调得很好了（`lambda_l1=205`、`lambda_l2=581` 是反复实验的结果）。自己乱调大概率是变差。

#### 「性价比最高的」和「预期最准的」差多少

这个理解方向对，但需要修正一个前提：**「预期最准」这件事在事前是未知的**。

实测数据（CSI300 / Alpha158，20 次运行均值）：

| 选择 | IC | 相对 LightGBM | 训练成本 | 口径 |
|---|---|---|---|---|
| LightGBM（性价比） | 0.0448 | 基准 | CPU 15 秒 | 实测 |
| DoubleEnsemble（表里最准） | 0.0521 | **+16%** | CPU，但慢 5~10 倍 | 实测 |
| 更深调的 LightGBM（假设） | 0.048? | +7%? | 未知 | **无法预知** |

**三个关键事实**：

1. **表里的「最准」只是「官方配置调得最好的」**，不是模型上限。README 自己承认：

   > We have very limited resources to implement and finetune the models... some models may have greater potential than what it looks like in the table.

2. **最好的模型只比基线好 16%**，而换数据集（Alpha158→Alpha360）或换股票池（csi300→csi500）带来的变化往往更大。

3. **「预期最准」只在事后知道**。事前你只有：
   - 官方基准表（20 次运行的均值±标准差）
   - 自己的实测

#### 所以模型选择应该怎么做

```
第 1 步：先跑 Linear + LightGBM 两个基线
         ↓ 如果复杂模型打不过这两个 → 问题在数据，不在模型
第 2 步：固定数据，只换模型，看官方基准表挑 2~3 个候选
         ↓ 注意看「标准差」，不只看均值
第 3 步：候选模型各跑 20 次（不同随机种子）
         ↓ 比较均值±标准差，而不是单次结果
第 4 步：选「均值最高 + 标准差可接受」的那个
```

**为什么必须跑多次**：模型有随机性。单次结果可能是运气。官方表的标准差列就是为此存在的：

| 模型 | IC | IC 标准差 |
|---|---|---|
| DoubleEnsemble | 0.0521 | ±0.00（很稳） |
| TabNet | 0.0204 | **±0.01（波动大）** |

TabNet 的波动比它的均值变化还大——**单次跑出 0.03 或 0.01 都正常**。

`examples/run_all_model.py` 就是干这个的：

```bash
cd examples && python run_all_model.py run 3 lightgbm Alpha158 csi300
```

#### 一句话

**性价比和精度不是对立的，但精度提升非常有限（±16%），而「跑 20 次看分布」比「挑最强的模型」更能避免你被运气骗。**

### 一句话总结

用一条数据的实际流向来说明这五层各自管什么：

```
┌─────────────────────────────────────────────────────────────────┐
│  交易所原始数据（第3层：数据干净度决定它准不准）                    │
│  date       open   high   low    close  volume                   │
│  2020-07-30 3.10   3.15   3.05   3.12   120000                    │
│  2020-07-31 3.12   3.20   3.10   3.18   150000                    │
└────────────────────────────┬────────────────────────────────────┘
                             │
            第2层：特征质量 ─┤ 用哪些公式把它变成「有预测含义的指标」
            （决定算什么）    │   ($close-$open)/$open  → KMID
                             │   Ref($close,5)/$close  → ROC5
                             │   Std($close,20)/$close → STD20
                             ↓
┌─────────────────────────────────────────────────────────────────┐
│  特征表：158 列数字，量级各不相同                                 │
│  KMID=0.019  ROC5=1.03  STD20=0.028  ...                         │
└────────────────────────────┬────────────────────────────────────┘
                             │
            第4层：数据加工 ─┤ 把数值换个形式（不改变「算什么」）
            （决定怎么摆）    │   ZScoreNorm: 拉到 mean=0, std=1
                             │   Fillna:     NaN → 0
                             ↓
┌─────────────────────────────────────────────────────────────────┐
│  加工后的特征：KMID=0.87  ROC5=-1.24  STD20=0.33  ...            │
└────────────────────────────┬────────────────────────────────────┘
                             │
            第5层：模型 ─────┤ 学「特征 → 收益」的映射
            （±15%）         │   LightGBM / LSTM / ...
                             ↓
                        预测分数 score
                             │
                             │  ← 第1层：标签定义决定这个「标准答案」是什么
                             ↓
                    真实收益 label（T+2 相对 T+1 的涨跌）
```

**五层各管一件事，互不重叠**：

| 层 | 管什么 | 一句话 | 影响 |
|---|---|---|---|
| 1. 标签 | **标准答案** | 你要预测的到底是什么收益 | 决定上限，改不了 |
| 2. 特征 | **输入指标** | 用什么信息去预测 | 影响最大（可调） |
| 3. 数据 | **原料真假** | 原始数据对不对、有没有混入未来信息 | 出错就全盘皆输 |
| 4. 加工 | **数值格式** | 算好的特征怎么缩放、怎么补缺 | 影响模型能否收敛 |
| 5. 模型 | **映射函数** | 特征到收益之间是什么关系 | ±15% |

**模型只能逼近数据的上限，它无法创造数据里不存在的信息。**

**注意**：第 2 层和第 4 层最容易混——区别就是**「算什么」vs「算完之后怎么摆」**。特征表里 `ROC5=1.03` 这个数（第 2 层决定），和第 4 层把它改成 `-1.24`（标准化），是两件不同的事。

## 六、提升效果的优先级

按性价比从高到低：

| 优先级 | 做什么 | 成本 | 收益 |
|---|---|---|---|
| 1 | **检查标签和前视偏差** | 不花钱 | 能救命 |
| 2 | **换更好的数据源**（复权因子、停牌处理） | 低 | 高 |
| 3 | **换数据集**（Alpha158 ↔ Alpha360） | 极低 | 高 |
| 4 | **换股票池**（csi300 ↔ csi500 ↔ all） | 极低 | 中高 |
| 5 | **换模型**（线性 → 树 → 集成） | 低 | 中 |
| 6 | **调超参** | 高 | 低 |
