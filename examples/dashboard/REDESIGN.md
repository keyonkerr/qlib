# 实验看板设计说明：从「读表」到「解剖」

这一版看板替换了早期「指标表 + 页签图表」的版本。记录当时的三个问题和处理方式，
方便以后改设计时知道为什么是现在这样。

可访问：`http://localhost:8766/`（重设计已完成合并，正式页即此设计）。

---

## 一、这次改了什么

早期的看板能读到全部数据，但读数据不等于看得懂。参数是一串 `model.kwargs.lambda_l1`，
指标是一串 `1day.excess_return_with_cost.information_ratio`，图表分成两种完全不同的
呈现方式（qlib 官方图用页签切换，自算序列平铺堆叠）。

重设计解决三件事：**参数和指标要有中文解释与判读标准**（四、术语词典）、
**图表要统一成一种呈现方式**（五、图版）、**索引要以 YAML 为维度而不是 run**（三）。

---

## 二、设计方向：测量记录纸 · 实验解剖

**页面是一张测量记录纸，不是仪表盘。**

仪表盘的默认语言是「大数字 + 小标签 + 卡片网格 + 柔和阴影」。这个项目的数据恰恰不适合
那种读法：一次实验有 19 个指标、26 个参数、871 天序列，扫一眼大数字并不能判断这次实验
好不好。判断来自**对比**——训练损失和验证损失比、含成本和无成本比、逐日 IC 的均值和
离散度比。

所以整页按「实验解剖」组织：这是一份标本，按身份、投料、配置原文、信号、执行、结果、训练、
原始记录、出处逐层剖开。每个数字都可以点开看它是什么、怎么算、怎么判读。

### 视觉基调

- **底纹是坐标纸**：冷灰底 + 24px/96px 两级极淡网格。网格不是装饰，是「测量」这个动作的
  视觉母题，所有图版和表格都压在同一张纸上。
- **只用两个重音色，各有一个职责**：普鲁士蓝（`#1E3A5F`）用于实测数据和当前选中；
  赭石（`#9C5B24`）用于第二条曲线和警告。没有第三种。
- **字体分工严格**：中文衬线（Noto Serif SC）只用于章节标题和结论，负责「读」；
  等宽字体（DM Mono）承载所有测量值，负责「比」；无衬线（Noto Sans SC）只写正文。
- **发丝线只有一个重量**：表格边框、图版边框、分隔线全部 1px 同级。层级靠留白和字号建立，
  不靠边框粗细。

刻意避开的默认套路：卡片圆角 + 统一柔和阴影、暖米色底 + 陶土色、荧光绿配近黑、
每个标题上方的小号全大写标签。

## 三、以 YAML 为维度，而不是 run

### 为什么

训练、验证、修改的对象都是配置文件，不是某一次运行。同一个 YAML 经常跑多次（`--repeat` 换 seed、或者单纯重跑），按 run 平铺会带来两个问题：

- 几十个 run 里大部分是重复的，真正不同的配置反而找不到
- 看到两个 run 的 IC 差 0.002，无法判断是改了配置，还是只是换了种子

### 索引结构

```
path_exps                     ← 实验（可折叠）
├── 00_baseline      2 次     ← 配置（扫描的一行）
│   ├── 种子 42    IC .0456   ← 该配置的每次运行，点击切换右侧
│   └── 种子 43    IC .0441
└── 31_linear        1 次
```

配置行显示 IC 和运行次数；跑过多次的配置额外显示 **IC 极差**（赭色 `±0.0029`），那是判断「配置是否真的有效」的基准。

### 同配置运行区

打开任一 run，右上角会多出一块「同配置运行」：

| 运行 | IC | 年化 | IR | 最大回撤 | 时间 | |
|---|---|---|---|---|---|---|
| 种子 42（当前） | 0.0456 | 10.80% | 1.19 | −8.92% | 11-17 | |
| 种子 43 | 0.0441 | 10.61% | 1.16 | −9.01% | 11-17 | 切换 |
| **极差** | **0.0015** | 0.19pp | 0.03 | 0.09pp | | |

下面还会给出一句判断：本次 run 的 IC 是否落在正常波动范围内。**比较两份不同 YAML 时，差异只有超过这个极差才算数。**

只跑过一次的配置会明确说明「波动范围未知」，并提示用 `run_all.py --repeat N`。

### seed 变体的识别

`run_all.py --repeat` 生成的是 `00_baseline_s43.yaml` 这样的临时文件，跑完就删。所以配置身份要在 run 落库时从文件名里解析：`store._config_identity` 把 `_s<数字>` 后缀拆出来作为 seed，剩下的作为分组键。否则每次重复运行都会变成一个独立配置，分组就失效了。

## 四、核心机制：术语词典

这是「自建平台」相对 MLflow 界面的唯一意义所在。

### 29 个可点开的术语

页面里任何带下划虚线的数字都能点开一张说明卡：

```
┌──────────────────────────────────────┐
│ 信号  IC · 信息系数          收起    │
├──────────────────────────────────────┤
│ 每天把全部股票的「模型打分」和「真实   │
│ 涨跌」做一次相关性，再把整段回测期逐日 │
│ 的相关系数取平均。                     │
│                                      │
│ 怎么算  Pearson 相关，逐日计算后取均值。│
│        源码 qlib/contrib/eva/alpha.py │
│ ------------------------------------ │
│ ≥ 0.03  低于 0.03 通常不足以支撑选股   │
│ ≥ 0.05  0.03–0.05 可用，A 股日频区间  │
│ ≥ 1.00  0.05 以上算强信号，先查泄漏    │
│ ------------------------------------ │
│ ⚠ 相关性不等于赚钱：高 IC 也可能被     │
│   换手和成本吃掉                       │
└──────────────────────────────────────┘
```

每条术语包含四个层次：**是什么**、**怎么算**（精确到源码位置）、**判读分档**、**常见误读**。

覆盖范围：

| 类别 | 术语 |
|---|---|
| 信号 | IC、ICIR、Rank IC、Rank ICIR、预测分数、标签 |
| 执行 | ffr 成交率、pa 价格优势、pos 胜率、换手率、交易成本 |
| 结果 | 年化超额、IR、最大回撤、标准差、日均超额、基准收益、持仓收益 |
| 训练 | 训练损失 l2、验证损失 l2 |
| 参数 | num_leaves、learning_rate、max_depth、lambda_l1/l2、colsample_bytree、subsample、股票池、数据切分、topk、基准 |

判读分档全部基于 qlib 源码里的实际口径，不是拍脑袋的经验值。例如：
- 年化超额是 `日均超额 × 238` 的**算术累加**，不是复利（`qlib/contrib/evaluate.py::risk_analysis`）
- ICIR 记录的是日均值，年化要 `× √238`
- `ffr/pa/pos` 在缺 `factor.day.bin` 时会同时退化（pa=0、pos=0、ffr=1），页面会单独标黄提示

### 原始记录表：原始键 → 值 → 人话

第七节把 19 个指标和 26 个参数排成三列表格：

| 原始键 | 值 | 含义 |
|---|---|---|
| `1day.excess_return_with_cost.information_ratio` | 1.1942 | 每承担一份波动，换来多少超额收益… |
| `model.kwargs.lambda_l2` | 580.9768 | 对叶子权重的平方惩罚，抗过拟合的主要旋钮… |

未收录解释的键会显式标灰「未收录解释」，而不是假装有。

## 五、图表的统一

### 问题

原页面有两种互不相干的图表：

- qlib 官方 Plotly 图：4 个页签 + 7 个 chip 切换，一次只看一张
- 自算序列图：平铺直列，一屏看不到底

同样是「图」，却要学两套操作方式。

### 方案：图版（plate）

所有图——不管是 Plotly 还是自算序列——都放进同一个组件：

```
┌────────────────────────────────────────────┐
│ 图 3  逐日换手率            871 个交易日    │
│ 每天换掉多少仓位。它自己不是问题，和下面   │
│ 那张成本图一起看才是问题。                  │
├────────────────────────────────────────────┤
│         ╱╲    ╱╲╱╲                          │
│    ╱╲╱╲╱  ╲╱╲╱    ╲╱╲╱                    │
│                                            │
│ 0.00                              0.28     │
├────────────────────────────────────────────┤
│ 均值 0.42%   95% 分位 1.13%                │
└────────────────────────────────────────────┘
```

每个图版都有：**编号**（便于在讨论中引用「图 3」）、**标题**、**一句读法**（这张图该看什么、
不该看什么）、**数据**、**统计带**。

官方图表不再用页签，而是按主题分组（净值与回撤 / IC 累积 / 模型表现 / 风险拆解图），
每张图依然是独立图版，有中文小标题和读法说明。

### 配置原文是快照，不是引用

qlib 只把**解析后**的配置记进 run（`artifacts/config`），YAML 原文和注释都不保留。最初看板按路径实时读源文件，问题很明显：

- 改了 YAML，历史 run 展示的配置会跟着变——等于篡改历史
- `run_all.py --repeat` 会写一个临时改 seed 的 YAML，跑完立刻删除，根本没有文件可引用

所以改成运行时拷贝：`examples/tools/snapshot_config.py` 把 YAML 写进 `artifacts/config_source.yaml`，随 run 一起保存。两个批量脚本都已接入。

读取优先级：**快照 → 回读磁盘**。回读只用于补快照之前的旧 run，且会把 YAML 的 `task` 子树反嵌套后与 MLflow 记录的参数比对；对不上就在页面上标红「内容已与 run 不符」。页面对三种来源分别有徽章：

| 徽章 | 含义 |
|---|---|
| 随 run 冻结 | 运行时快照，可信 |
| 回读源文件 | 无快照，读磁盘当前文件；参数一致时也标注 |
| 内容已与 run 不符 | 无快照且源文件已被改动，明确提示不可信 |

### 性能：分批自动挂载

14 张 Plotly 页面每张约 3MB，一次性全挂会拖垮首屏。但让用户逐张点「展开」也不合适——
图表本该直接可见。折中：页面渲染完后按文档顺序分批挂载，先 2 张，其余利用
`requestIdleCallback` 每批 4 张补齐。读者滚动到图表区时，图已经在那里了。

## 七、具体改进对照

| 原页面 | 重设计 | 为什么 |
|---|---|---|
| 5 个摘要指标平铺 | 按信号/执行/结果/训练分组，每组带导读 | 指标不是同质的，混在一起无法判断 |
| 「净值与回撤」「IC 累积」等页签 | 图版，按主题分组 | 页签隐藏内容，读者不知道还有几张 |
| 自算序列平铺直列 | 同样是图版，带编号和读法 | 统一交互，一张图一个读法 |
| 参数直接列原始键 | 三列表：原始键 → 值 → 含义 | 原始键对新手不可读 |
| 配置只有解析后的值 | 新增「配置原文」节，读 YAML 快照 | 注释解释了每个参数为什么这么设，解析后的值把它们全丢了 |
| 配置按路径实时读取 | 运行时把 YAML 冻结进 run 产物 | 改配置不该改写历史 run；临时 seed 文件跑完即删 |
| 指标直接列原始键 | 同上，且可点开判读标准 | 知道数值不等于知道好坏 |
| 无图时显示「这个 run 还没有图表」 | 图版仍列出，标注「未生成」 | 知道缺什么比只看空态更有用 |
| 图表全部同时加载 | 分批自动挂载 | 图直接可见，首屏又不被 14 张 Plotly 拖慢 |

## 八、仍有取舍

- **判读分档是 A 股日频的经验值**。换市场、换频率必须重新标定，`analysis.py` 顶部有常量。
- **训练曲线共用纵轴时会压扁验证线**。这是数据真相（0.9636 对 0.9945），不是绘图错误。
  页面用「末轮差距」「验证最低」两个数字补足肉眼看不到的部分。
- **Playwright 图内部字体与页面不一致**。要统一得改 `report_graphs.py` 给官方绘图函数传
  `layout.font`，属于动上游图表，暂未做。
- **没有前端路由**。刷新回到第一个有图的 run。要分享具体 run 需要加 hash 路由。
